## 한 문장 요약

Wikipedia로부터 자동 생성한 구조화된 지식 트리와 간선 단위의 근거 기반 루브릭을 사용해 전문적 딥리서치 에이전트의 '구조화된 지식 커버리지(폭·깊이)'를 주요 평가 목표로 삼는 벤치마크 DRBench Pro를 제안하고, 토폴로지 인지형 집계 지표로 폭·깊이를 분리 측정해 16개 에이전트를 비교·분석하였다.

## 해결하려는 문제

기존 딥리서치 평가들은 사실성, 문체, 인용 품질 등 여러 차원을 평가하지만, 보고서가 어떠한 연구 방향들을 다루었는지(폭)와 해당 방향들에서 관련 지식 사슬을 얼마나 연속적으로 깊게 추적했는지(깊이)를 구조화된 참조 공간 관점에서 전담하여 정량화하는 평가가 부족하다. 또한 자동 생성 기준을 평탄하게 집계하면 항목 간 구조적 관계가 소실되어 ‘방향별 폭’과 ‘사슬 전체의 깊이’라는 서로 다른 특성을 제대로 드러내지 못한다.

## 핵심 기여

- DRBench Pro라는 지식 중심 벤치마크를 제안: Wikipedia 기반 로컬 지식 트리를 자동 구축하고, 샘플된 부분그래프(subgraph)로부터 같은 구조를 공유하는 연구 쿼리(입력)와 간선(관계) 단위의 근거 기반 루브릭(숨김 평가 기준)을 생성하여 총 144개 케이스·24개 도메인·44,102개 루브릭으로 구성.
- 토폴로지 인지형 메트릭(브레드스·뎁스)과 전체 커버리지 정의: 간선 수준 판정을 트리 구조에서 하향(leaf→root)으로 재귀 집계해 '연구 방향별 폭(Breadth)'과 '지식 체인 연속성 기반 깊이(Depth)'를 분리 계산하고 이들의 기하평균을 전체 커버리지로 사용.
- 자동화된 벤치마크 생성 파이프라인과 반유출(query leakage) 제어: 루트 확장(최대 3-hop), 루트 당 10개 브랜치 보존, Claude Opus 4.8을 활용한 분기 선정·쿼리·루브릭 생성, 쿼리에서 숨김 엔티티 이름을 금지하는 프롬프트로 유출 위험 최소화.
- 실험적 검증: 16개 딥리서치 에이전트(Deep Research 시스템·네이티브 서치 LLM·로컬 리서치 프레임워크 백본)를 평가하여 에이전트별 폭·깊이 프로파일을 노출하고, 루브릭 수준과 리포트 수준에서 인간 레이블과의 일치성(예: 루브릭 이진 Macro-F1=0.893, 리포트 수준 Kendall τb 전체=0.751 등) 및 메트릭 안정성 분석을 제시. 

## 접근 방법

* 벤치마크 구성: (1) 도메인 선택: WebOrganizer의 24개 주제 범주에서 도메인별로 2개 루트 엔티티를 선택(총 48 루트).
* (2) 로컬 지식 그래프 구축: 각 루트에서 위키피디아 링크를 breadth-first로 확장하되 트리 형태(각 노드 하나의 부모, 최대 3-hop, 루트 자식 50개 제한, 비루트는 각 노드 최대 5자식)를 유지하여 로컬 지식 트리 생성.
* (3) 서브그래프 샘플링: 루트와 10개 완전 브랜치(branch)를 보존하고, Claude Opus 4.8을 사용해 루트의 자식들을 조직적으로 그룹화하여 루트당 3개의 케이스(총 144 케이스) 생성.
* (4) 쿼리·루브릭 생성: 각 샘플 서브그래프에서 동일한 구조 정보를 이용해 루트 중심의 자연어 연구 쿼리를 생성하고, 서브그래프의 각 간선(edge)에 대해 해당 간선의 출처·타깃 페이지의 요약과 앵커 문맥을 근거로 '관계 커버리지 요구사항' 형태의 루브릭을 생성(각 루브릭은 그 간선의 트리 내 위치와 hop distance를 보유하되 평가 시에는 숨김).
* (5) 평가·메트릭: 평가자는 에이전트가 생성한 리포트와 루브릭 세트를 받아 각 루브릭에 대해 Gemini 2.5 Pro를 판정(Satisfied/Partially/Not)하도록 하고, 집계에 앞서 Satisfied→1, others→0으로 이진화.
* 집계는 트리 구조를 보존하며 leaf→root 방향으로 재귀적으로 결합: breadth는 브랜치 간 평균을 통해 방향별 포괄성을 평가하고, depth는 사슬 연속성에 보상/할인 규칙을 두어 연결성(continuity)을 강조.
* 케이스 수준 breadth Bc와 depth Dc의 기하평균 Sc = sqrt(Bc * Dc)를 케이스 점수로 삼고, 144 케이스 평균을 최종 점수로 사용.
* 로컬 리서치 프레임워크: 검증 재현성을 위해 고정된 Wikipedia 스냅샷(enwiki-20260701-v1)과 Search/Open 도구, 고정 연구 유닛 수(초기 3 유닛, 최대 1개 gap 유닛, 총 최대 4), 라운드·툴 콜·토큰 한도 등 표준화된 인터페이스를 제공.

## 주요 결과

- 데이터셋 규모: 24개 도메인, 48 루트에서 샘플된 144 케이스, 총 44,102개의 간선 단위 루브릭(각 간선당 하나의 루브릭).
- 에이전트 평가(16개): 최고 성능은 Claude Opus 5로 Overall Coverage 57.04%, Breadth 53.09%, Depth 61.91%. 2위 Grok 4.5 Overall 50.98%. Deep Research Systems(예: o3 Deep Research)는 Depth에서 강점(예: o3 Overall 49.45, Breadth 45.77, Depth 54.32) 보임. (Table 2).
- 인간 일치성: 루브릭 수준의 LLM 판정(이진 매핑)과 인간 레이블의 Macro-F1: Gemini 2.5 Pro = 0.893(이진), Qwen 3.8 Max = 0.840, DeepSeek V4 Pro = 0.865. 리포트 수준 메트릭과 전문가 평정(3인 평균) 간 상관: Overall Kendall τb = 0.751, Spearman ρs = 0.833; Breadth τb=0.696·ρs=0.777, Depth τb=0.727·ρs=0.813 (Table 5).
- 메트릭·순위 안정성: 메트릭 하이퍼파라미터(예: α, η, ρ, β) 변형 실험에서 에이전트 순위는 대체로 안정적(Spearman ≥ 0.976–1.000), 단 α 증가(0.25→0.40)는 depth에서 일부 실질적 순위 역전(practical reversal)을 일으킬 수 있음(Table 7).
- 유출(Leakage) 점검: 쿼리에서 숨김 엔티티명이 노출되는지 수동검사(7,385 쌍) 결과 확인된 유출 8건(0.108%), 1-hop에서는 0건(Table 4).

## 한계

- 저자 명시 한계: (1) 구성 모델 민감도: 벤치마크·루브릭·쿼리 생성에 사용한 모델(Claude Opus 4.8) 영향 가능성 언급 및 Kimi K2.6으로 재구성한 10개 샘플에서 Claude의 우위가 축소되지만 여전히 유지됨—즉, 구성 모델 선택이 결과에 일부 영향. (본문 섹션 4.7, Table 8).
- 저자 명시 한계: (2) 메트릭 파라미터 민감도: depth 점수는 α의 값 변화에 민감하여 지나치게 큰/작은 α는 의도한 깊이 정의와 맞지 않음(섹션 4.6).
- 본문에서 합리적으로 확인되는 제약(추정 아님 아님): (3) 지식원 한정성: 하나의 고정된 Wikipedia 스냅샷(enwiki-20260701-v1)을 참조하므로 최신성·전문자료(학술문헌·비위키 출처) 부족에 따른 커버리지 한계가 있음(로컬 리서치 프레임워크 설명과 설계에서 확인).
- 본문에서 합리적으로 확인되는 제약: (4) 루브릭 이진화로 인한 정보 손실: 판정 결과를 이진(1/0)로 변환해 '부분 만족(0.5)'의 미묘한 차이를 메트릭 집계에서 반영하지 않음—저자도 이진 매핑을 채택했으며 이로써 Macro-F1이 높아짐을 보고함(섹션 3.4·4.5).

## 개발자 관점

- 재현 가능성: 저자들이 코드·프롬프트와 고정 Wikipedia 스냅샷(enwiki-20260701-v1)을 공개했으므로 동일한 로컬 리서치 툴(Search/Open)과 워크플로우(초기 3 Research Units, 최대 1 Gap Unit, 단위별 모델 라운드·툴 콜 제한)를 구현하면 비교 가능 평가 가능(부록 F, Table 26).
- 구성·평가 비용: 벤치마크 구성 전체 비용(Claude Opus 4.8 사용) 약 USD 1,610.61(48 루트 기준), 리포트 생성(16 에이전트, 144 케이스) 총 모델 콜 비용 약 USD 1,069.27, 판정 비용 Gemini 2.5 Pro 총 USD 629.11 등 실제 API 비용을 포함한 예산 산정이 가능(부록 H).
- 루브릭·쿼리 생성 파이프라인 구현 주의사항: 생성 시 '안티-유출' 규칙(쿼리에 숨김 엔티티 이름·서브그래프 타이틀 금지)을 엄격히 적용해야 하며, 생성 모델에 따라 구성 편향이 생길 수 있으므로 다른 생성 모델로 재구성해 민감도 점검 권장(섹션 3.3·4.7).
- 판정자(judge) 선정 및 검증: 자동 판정자 모델(Gemini 2.5 Pro)을 사용하되 인간 라벨과의 일치성(루브릭 레벨 Macro-F1) 검증을 필수로 수행하고, 필요하면 이진/삼원(ternary) 판정 전략과 변환 규칙을 문서화할 것(섹션 4.5).
- 메트릭 파라미터·해석 지침: 폭·깊이 집계 파라미터(예: α=0.25, η=0.75, ρ=0.50, β=0.60의 기본 설정)를 명시적으로 고정·보고하고, 민감도 분석을 통해 해석상의 한계를 사용자에게 안내할 것(Table 7).

**근거 범위:** 분석은 제공된 논문 PDF 본문(주요 본문과 부록에서 인용된 표·숫자·절차)을 기반으로 작성됨. 본문에서 명시적으로 언급된 수치(예: 케이스 수 144, 루브릭 총수 44,102, 최고 성능 Claude Opus 5 Overall 57.04%, 루브릭 이진 Macro-F1 0.893, Wikipedia 스냅샷 enwiki-20260701-v1 등)만 사용했음. 일부 세부 구현·추가 파라미터(부록의 완전한 알고리즘 행렬, 소스 코드의 내부 변수)는 본문에 요약되어 있으나 PDF 추출 범위상 전체 부록의 모든 줄·표를 완전 대조하지 못한 부분이 있을 수 있으니, 재현·세부 구현은 공개된 코드와 프롬프트(저자 제공 저장소)를 함께 확인하기 바람.
