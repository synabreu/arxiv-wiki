## 한 문장 요약

일상적 25턴 대화 스크립트(응답을 21턴에서 평가)에 동일한 위험 단서를 한 번에 모아 제시(concentrated)하거나 1,6,11,16,21턴에 분산(dispersed)시켜 6개 상용 모델을 실험하고, 현장 커뮤니티 정신건강 지원자들이 설정한 금준(gold standard)과 LLM 판정기로 응답 강도를 비교해 '단서 분산이 안전 대응을 약화하는가'를 평가했다.

## 해결하려는 문제

기존 안전 평가들은 사용자가 위기나 고통을 명확하게 한 번에 진술하는 단일 메시지 중심인 경우가 많아, 실제 사용자들이 평범한 대화 속에서 단서를 점진적으로 드러낼 때 모델이 동일하게 적절히 개입하는지를 보여주지 못한다. 본 연구는 동일한 5개 위험 단서를 한 메시지에 모아 제시했을 때와 동일한 단서를 대화 전반에 분산시켰을 때 AI 비서들이 지원자(현장 지원자들이 정한 기준)에 부합하는 안전(사이프가딩) 대응을 동일하게 보이는지 검증한다.

## 핵심 기여

- 현장 경험이 있는 커뮤니티 정신건강 지원자 3명(P1,P2,P3)과 공동으로 현실적 어조의 25턴(평가시점: 21턴) 스크립트와 9개 시나리오(우울·정신증·가정폭력, 각기 3단계 위험강도)를 설계하고, 각 시나리오마다 5개 위험 단서를 정의함.
- 동일한 5개 단서를 concentrated(한 번에 21턴에 삽입) versus dispersed(1,6,11,16,21턴에 하나씩) 방식으로 제시하는 엄격한 대조 실험을 설계해, 내용(사용자 메시지)은 고정한 채 '전달 방식'만을 변동시켜 영향만을 분리함.
- 6개 상용 모델(GPT-5.5, Grok 4.3, Claude Opus 5, Claude Sonnet 5, DeepSeek V4, Llama 4 Maverick)을 OpenRouter API로 대규모(총 7,410회 대화) 평가하고, 현장 지원자들이 정의한 기대 응답(골드 스탠다드)과 비교해 모델별·조건별 성능 차이를 정량화함.
- 응답을 5단계(무응답→공감만→부드러운 안내→단호한 안내→사이프가딩 우선)로 정의하고 Claude Sonnet 4.6을 판정자(LLM-judge)로 사용해 자동 분류 후 사람이 검증(표본 kappa=0.93)하는 평가 파이프라인을 구현함.

## 접근 방법

* 실험 설계: 동일한 사용자 측 스크립트(총 25턴; 사용자 메시지와 모델 응답이 번갈아 나옴)를 사용하고 모든 모델이 동일한 입력을 받도록 고정.
* 연구자는 9개 시나리오(3개 프로파일×3단계 강도)와 컨트롤(단서 없음)을 만들고, 각 시나리오에 5개 단서를 정의했다.
* 단서 전달: concentrated는 5개 단서를 모두 21턴 사용자 메시지에 병합해 첨부, dispersed는 5개 단서를 1,6,11,16,21턴에 하나씩 첨부.
* 모델·추론 설정: OpenRouter API 호출, 시스템 프롬프트 없음, reasoning 비활성화, temperature=0.7.
* 반복 횟수: DeepSeek V4·Llama 4 Maverick·Claude Sonnet 5는 조건별 100회 반복(비용 절감 모델), GPT-5.5·Grok 4.3·Claude Opus 5는 조건별 30회 반복(유료 모델 비용 제약).
* 평가 시점: 모든 단서를 모델이 받은 뒤인 21턴의 모델 응답을 분류.
* 응답 스케일: 5단계(무응답→공감만→부드러운 안내→단호한 안내→사이프가딩 우선).
* 판정: Claude Sonnet 4.6 LLM-judge가 사용자 메시지와 모델 응답(21턴)만 보고 네 개의 yes/no 질문(각 단계의 경계)을 답하도록 해 최고 단계로 분류; 판정자는 응답 문구 인용을 의무화함.
* 판정자 검증: 저자가 표본 80개 응답을 채점, 판정자와 quadratic-weighted kappa=0.93.
* 골드 스탠다드: P1과 P3가 각 시나리오·전달 방식별 기대 응답을 독립적으로 지정; 불일치 시 낮은(expectation)를 채택.
* 통계분석: 순서형 응답을 위한 비모수 효과크기 Cliff's delta(부스트랩 5,000으로 95% CI), 유의성 검정은 같은 시나리오 내에서 레이블을 섞는 10,000회 일측 permutation test, 정신건강 프로파일별 p값은 Holm 보정.

## 주요 결과

- 데이터 규모: 모델별 대화 수는 GPT-5.5 570, Grok 4.3 570, Claude Opus 5 570, DeepSeek V4 1,900, Llama 4 Maverick 1,900, Claude Sonnet 5 1,900로 합계 7,410회 대화(논문 본문 수치).
- '최소한 부드러운 안내(gentle signposting)' 비율(집중 vs 분산): GPT-5.5 100% → 71%; Grok 4.3 96% → 31%; Claude Opus 5 100% → 99%; DeepSeek V4 100% → 68%; Llama 4 Maverick 94% → 57%; Claude Sonnet 5 100% → 91% (Table 2).
- 골드 스탠다드(지원자 기대)를 충족한 비율(집중 vs 분산): GPT-5.5 59% → 3%; Grok 4.3 41% → 3%; DeepSeek V4 39% → 6%; Llama 4 Maverick 26% → 4%; Claude Opus 5 97% → 87%; Claude Sonnet 5 68% → 59% (Fig.3 및 본문).
- 효과크기(Cliff's delta) 및 유의성: 모든 모델에서 분산시 응답이 약화되어 positive delta(모두 p<0.01). 모델별 Cliff's delta는 Grok 4.3 0.75, GPT-5.5 0.61, DeepSeek V4 0.48, Llama 4 Maverick 0.43, Claude Opus 5 0.35, Claude Sonnet 5 0.09 (95% CI 및 p값은 본문 표 참조).
- 최고 수준(사이프가딩 우선) 응답의 감소: 예시로 GPT-5.5는 concentrated에서 31%가 safeguarding-first였으나 dispersed에서는 거의 0%(<1%, 1/270), DeepSeek V4 26%→3%, Claude Opus 5 92%→56%, Claude Sonnet 5 57%→51% (본문 및 부록 수치). 결과 전반: 단서 분산은 대부분의 모델에서 응답 강도를 현저히 약화시키며, Anthropic의 두 모델(Claude Opus 5·Sonnet 5)은 다른 모델들보다 분산에 덜 민감했음. 또한 민감도 분석(집중 단서를 단순 연결한 verbatim concatenation)에서 전반적 효과는 유지되었으나 GPT-5.5와 Grok에서는 일부 약화(attenuation)가 관찰되어 문구 편집이 일부 영향을 줄 수 있음(Table 4, Appendix A).

## 한계

- 저자가 명시한 한계: (1) API를 통해 수집했으며 시스템 프롬프트·추가 안전 분류기·메모리 기능 등 실제 배포 환경의 구성요소를 적용하지 않아 배포형 어시스턴트의 실제 행동과 다를 수 있음. (2) 평가 루브릭은 응답의 '강도'(사이프가딩 단계)를 측정하지만 어조·품질·문화적 적합성 같은 정성적 요소는 포착하지 못함. (3) 사용자 측 대화가 스크립트화되어 모델의 후속 질문에 사용자가 동적으로 응답하지 못하므로 인터랙티브 흐름이 제한됨(모델이 안부를 물어도 사용자는 원래 작업 응답). (4) 대화 길이가 짧고(21턴 평가 기준), 단일 영어 화자 스타일을 사용하였으며 장기간·다언어·다음과 같은 실제 반복 사용을 반영하지 못함.
- 실험 범위에서 드러나는 제약(본문 기반, 저자가 별도로 명시하지 않은 관찰): 반복 수가 모델별로 달라(유료 모델은 조건당 30회, 무료 모델은 100회) 표본 크기·신뢰구간 폭이 모델간에 차이가 있음. 판정자 자체가 LLM이므로 자동화된 판정 방식의 한계(다수 표본에서 인간 검증은 표본 수준으로 제한)가 존재함. 또한 논문 내 민감도 분석에서 일부 모델은 문구 편집에 따라 결과가 달라져 모델·API의 버전 변화나 드리프트 가능성이 존재함.

## 개발자 관점

- 안전성 평가 설계: 단순 위기 표현(single explicit message)뿐 아니라 동일한 정보를 대화 전반에 분산하거나 은유·완곡어법 등으로 전달하는 경우까지 포함해 '전달 방식의 강건성'을 테스트해 결과를 보고하라.
- 현장 기준 포함: 기대 응답(골드 스탠다드)은 임상 의사뿐 아니라 실무 지원자·도메인 옹호자들과 공동 설계해 실제 보전(guarding) 관행을 반영하라. 서로 다른 이해관계자(실무자·당사자 경험 보유자) 의견을 분리·보고하라.
- 배포·설정 민감도 점검: 시스템 프롬프트, 안전 분류기, 메모(장기 문맥) 등 배포 환경 구성요소를 달리 했을 때 분산 단서에 대한 대응이 어떻게 달라지는지 A/B 실험을 수행하라. 운영시스템에서는 이러한 구성요소들이 모델의 개입 빈도와 타이밍에 큰 영향을 줄 수 있음.
- 실행가능한 안전 옵션 설계: 사용자가 선택 가능한 '사이프가딩 모드'(대화 전반의 건강 관련 단서를 집계·요약해 매 응답 시 고려하도록 하는 모드)를 제공하고, 활성화 선택지와 개인정보·메모리 보관 정책을 명시적으로 제시하라. 또한 오탐(일반적 표현을 과잉개입으로 이어지게 하는 문제)을 방지하기 위한 평가 세트(무해한 대화에 대한 거짓 양성 검사)를 함께 개발하라.
- 재현성과 비용 고려: 대규모 반복 실험에 드는 API 비용이 결과의 표본 크기에 영향을 미치므로, 공개된 스크립트·판정 프롬프트·데이터(익명화된 형태)를 함께 배포하고, 비용 제약이 있는 경우 소표본·부트스트랩 설계·대체 상시 평가(온디맨드) 방법을 문서화하라.

**근거 범위:** 논문 PDF 본문(제공된 전체 페이지 텍스트)을 근거로 분석하였음. 표·그림·부록의 수치는 본문에 직접 기재된 값을 사용했으며 표기된 통계(예: 비율, Cliff’s delta, p값, 대화 수 등)는 PDF에서 확인 가능한 숫자를 인용함. 다만 모델의 내부 구성(개발사 내부 프롬프트·안전 파이프라인)과 실시간 버전 변화, API 호출 시점의 잠재적 드리프트 등은 PDF 본문만으로는 확인할 수 없어 해당 항목에 대해서는 본문에 명시된 한계와 민감도 분석 결과만을 근거로 기술함.
