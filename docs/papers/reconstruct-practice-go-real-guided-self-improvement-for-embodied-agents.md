## 한 문장 요약

RPG는 오프라인 데이터에서 로봇 조작 역량을 자동으로 식별하고 시뮬레이션 기반 연습을 통해 상징적 스킬과 시스템 프롬프트를 반복적으로 개선하여(모델 가중치 갱신 없이) 다중 조작 과제에서 성공률을 크게 향상시키는 프레임워크이다.

## 해결하려는 문제

로봇이 다양한 조작 과제에서 안정적으로 동작하려면 스킬 설계, 보상 설계, 지각과 제어의 통합 등에 많은 인간 노력이 필요하다. 기존 방법들은 보통 모델 파라미터 업데이트나 인간의 수동 튜닝에 의존하고, 실패 원인 진단과 재사용 가능한 스킬의 자동 생성·정제 체계가 부족하다. 본 연구는 모델 가중치를 업데이트하지 않고도 실행 시스템을 자율적으로 개선하여 실제 로봇 성능을 높일 수 있는지와 그 절차를 묻는다.

## 핵심 기여

- RPG(Reconstruct, Practice, Go Real)라는 가중치 갱신 없이 로봇 실행 시스템을 자율 개선하는 프레임워크를 제안했다.
- 오프라인 데이터로부터 조작 역량을 식별하고, 관련 연습 과제를 시뮬레이션에서 구성하여 자동으로 연습할 수 있는 절차를 제시했다.
- 실행 피드백, 시뮬레이터의 프리비ileged 상태, 데이터셋 비디오를 이용한 실패 진단을 통해 신규 재사용 가능 상징(Semantic/symbolic) 스킬을 생성·정제하고 시스템 프롬프트를 수정하는 방법을 제시했다.
- 교차 과제 평가로 개별 후보 변경사항과 병합된 수정안을 시험한 뒤 보존하는 검증 절차를 포함하여 변경의 안전한 통합을 보장했다.
- 22개 조작 과제의 홀드아웃 초기화에서 반복 연습을 통해 성공률을 28.6%에서 95.0%로 개선하고, 물리 실험(세 과제, 총 30회 시행)에서 동결된 시스템이 모든 시도에서 성공함을 보였다.

## 접근 방법

* RPG는 다음 절차로 동작한다.
* (1) 오프라인 조작 데이터셋을 분석하여 현재 시스템이 가진 조작 역량과 실패 사례를 재구성(reconstruct)한다.
* (2) 이 역량과 실패 정보를 바탕으로 시뮬레이터에서 연습(practice) 과제를 자동 생성한다.
* 시뮬레이션 연습 동안 RPG는 실행 피드백, 시뮬레이터의 권한(privileged) 상태 정보, 그리고 이용 가능한 데이터셋 비디오를 사용해 실패 원인을 진단한다.
* (3) 진단에 따라 재사용 가능한 상징적 스킬을 새로 개발하거나 기존 스킬을 정제하고, 시스템 동작을 조율하는 멀티모달 LLM의 시스템 프롬프트를 수정한다.
* (4) 교차 과제 평가(cross-task evaluation)를 통해 각 개별 후보 변경사항과 병합된 수정안을 평가하고 성능 향상이 검증된 변경만 라이브러리에 보존한다.
* (5) 실제 테스트 시점에는 멀티모달 LLM이 최종 시스템 프롬프트와 스킬 라이브러리를 사용하여 지각과 로봇 제어를 조정한다.
* 전체 과정에서 모델의 가중치는 업데이트하지 않는다.

## 주요 결과

- 평가 환경: 홀드아웃 초기화된 22개 조작 과제에서 실험을 수행했다.
- 반복 연습 성과: 첫 연습 라운드 후 전체 평균 성공률은 28.6%였고, 15라운드 후 평균 성공률은 95.0%로 개선되었다.
- 비교 대상: RPG는 평가한 모든 베이스라인을 능가했으며, 예시로 ASPIRE의 성공률은 75.5%였고 CaP-Agent0( GPT-6 Astra Pro 기반)는 60.0%였다.
- 물리 실험: 공통 보정 및 하드웨어 적응 절차 후 동결된 시스템은 세 가지 과제에서 각각 10회, 총 30회 시행을 수행했으며 모든 30회에서 성공을 기록했다.

## 한계

- [저자 언급] 본문(제공된 텍스트)에는 저자가 직접 명시한 한계가 포함되어 있지 않다.
- [발견/추론] 방법은 오프라인 데이터와 시뮬레이터의 프리비ileged 상태에 의존하므로 고충실도 시뮬레이션과 시뮬레이터 내부 상태 접근이 필요해 실제 환경으로의 일반화·이식성에 제약이 있을 수 있다.
- [발견/추론] 물리적 검증은 세 과제에 대해 총 30회 시행으로 제한되어 있어 대규모 혹은 더 다양한 실제 환경·하드웨어에서의 성능 보장은 추가 실험이 필요하다.
- [발견/추론] 멀티모달 LLM과 시뮬레이션 기반 연습을 활용하므로 계산 비용과 시뮬레이션 구축·유지 비용, 그리고 대형 LLM 사용에 따른 운영비용이 증가할 가능성이 있다.

## 개발자 관점

- 재현: 논문은 가중치 업데이트 없이 시스템 프롬프트와 상징적 스킬 라이브러리를 개선하는 워크플로우를 제시하므로, 재현을 위해서는 원본 오프라인 데이터셋, 시뮬레이터(프리비ileged 상태 접근 가능), 그리고 멀티모달 LLM 인터페이스가 필요하다.
- 구현: 실패 진단에 시뮬레이터 내부 상태와 데이터셋 비디오를 결합하므로 시뮬레이터-실행 시스템 간의 로깅·동기화 구현이 중요하다. 또한 후보 변경을 안전하게 시험하는 교차 과제 평가 인프라가 필요하다.
- 배포: 런타임에서는 모델 가중치를 변경하지 않으므로 운영 중 모델 배포 복잡성은 낮출 수 있으나, 시스템 프롬프트·스킬 라이브러리 버전 관리 및 변경 승인 파이프라인이 필수적이다.
- 비용: 시뮬레이션 연습과 멀티모달 LLM 호출이 비용의 주요 원인이므로 고충실도 시뮬레이터 유지비와 LLM 사용량을 고려한 예산 산정이 필요하다.
- 안전성: 자동으로 스킬을 생성·병합하는 절차가 포함되므로 물리적 시험 전 시뮬레이션 기반 검증과 교차 과제 평가를 엄격히 수행하고, 실제 하드웨어에서의 안전 제한(속도·영역·힘 제한 등)을 명시적으로 적용해야 한다.
