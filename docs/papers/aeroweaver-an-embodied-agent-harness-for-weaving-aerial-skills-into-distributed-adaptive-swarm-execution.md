## 한 문장 요약

AeroWeaver는 자연어 미션 해석을 실행 가능한 'Aerial Skills'에 바인딩하고 역할별 로컬 에이전트와 역할-인덱스 보상 경험을 결합해 분산 UAV 군집의 실행과 온라인 적응을 지원하는 임베디드 에이전트 하네스다.

## 해결하려는 문제

기존 LLM 기반 군집 제어는 (1) 언어 수준의 결정이 실제로 실행 가능한 플랫폼 기능으로 연결되는 경계가 약하고, (2) 미션 수준의 글로벌 추론과 각 기체의 바디-로컬 분산 실행 정보 토폴로지가 불일치하며, (3) 수행 경험을 현재 의사결정에 연속적으로 반영해 안정적으로 적응시키는 방법이 체계화되어 있지 않다. 본 논문은 이들 문제를 해소하기 위해 언어-결정→실행 기능의 접합, 역할-조건 분산 조율, 실행 경험 기반의 온라인 보정 메커니즘을 통합하는 실행 런타임(하네스)을 제안한다.

## 핵심 기여

- 임베디드 에이전트 하네스와 Aerial Skills: 각 스킬을 문서(skill.md)와 실행 객체로 결합한 타입화된 스킬 패키지를 정의하고, 역할별로 활성 스킬 부분집합을 바디-스코프 실행자에 라우팅하는 인터페이스를 제시함.
- 분산 군집 오케스트레이션: 미션으로부터 역할-조건화된 프롬프트와 활성 스킬 집합을 도출하고, 각 로컬 에이전트를 UAV에 바인딩해 중앙 행동 제어기 없이 지향(peer-directed) 메시지로 조정하는 실행 구조를 설계함.
- 경험-유도 온라인 강화(Training-free): 역할-인덱스(state–action–reward) 메모리를 유지하고 유사 상태에서 스킬별 이점을 추정(bA)해 선택 스코어를 보정하는 무그래디언트 온라인 업데이트를 도입함(식(4),(5)).
- 시스템 구현·평가: AirSim 기반 MPE 유사 시나리오 9개(task)에서 DeepSeek V4-flash 백본을 중심으로 비교 실험을 수행해 중앙집중형 및 HMAS-2 기반 대안 대비 성능·토큰 비용 이점을 보고함.
- 공개 코드 배포: 논문에서 구현한 하네스와 스킬 구조를 코드 저장소로 공개함(논문 본문에 링크 기재).

## 접근 방법

* AeroWeaver는 세 부분으로 구성된다.
* (A) Aerial Skill Harness: 스킬을 σi = ⟨ni, di, Ii, Oi, Pi, Ei, Mi⟩ 형태로 정의하고, 운용자는 자연어 지시 q와 군집 상태 st로부터 미션 레코드 χt를 파싱해 태스크-레벨 후보 카탈로그 At를 검색·랭킹한다.
* Commander 컨텍스트에서 각 UAV에 역할 ρk와 지역 목표 gk를 할당하고 qk = Pack(q, ρk, gk)를 구성한 뒤 Lk = TopKσ∈At{rk(qk, σ)}로 활성 스킬 집합을 산출해 각 바디-바운드 에이전트에 전달한다.
* (B) Distributed Swarm Orchestration: 각 에이전트 k는 바디-로컬 관측 otk, 역할·목표·스킬 문서, 분리된 상호작용 이력(ctk)을 가지며 라운드 t에 atk = πsem(ctk, otk, {mt−1ℓ→k}ℓ∈Ntk, Lk)을 선택한다.
* 통신은 반경 rcomm 내의 이웃 Ntk로 제한되며 수신 메시지는 다음 라운드의 로컬 의사결정 컨텍스트에 들어가지만 실행 권한은 이전되지 않는다.
* 실행 시 잘못된 호출은 자기 바디 정지(hold)를 발생시킨다.
* (C) Experience-Guided Online Reinforcement: 실행 기록을 역할-인덱스 메모리에 (ρt, st, σt, at, rt, Gt) 형태로 저장한다.
* 의사결정 시 메모리에서 동일 태스크·역할을 필터하고 최대 32개(자카드 유사도로 정렬)를 복원해 각 스킬의 평균 반환 ¯Gi,ρ(s)와 역할 평균 ¯Gρ(s)를 계산하고 bA(s, σi)=¯Gi,ρ(s)−¯Gρ(s)로 스킬 이점을 추정한다(일치하는 경험이 없으면 0).
* 선택기에서 공급한 베이스 점수 zi에 대해 점수 보정은 z'i = zi + β bA(s, σi) (β≥0)이며 실험에서는 γ=0.95, β=0.8를 사용했다.
* 구현 상 세부: 선택기는 최대 20개의 대안 점수를 요청하고, 파라미터별 기본 점수는 별도이나 동일 스킬에 대해 스킬 이점을 공유한다; 후보 집합 L은 업데이트 동안 고정된다; β=0이면 기본 선택기로 복귀한다.

## 주요 결과

- 평가 설정: AirSim 기반 시뮬레이터에서 MPE 영감을 받은 9개 태스크(coverage, pursuit-evasion, guided navigation, private communication, circular formation, line formation, world communication, collection-delivery, goal concealment)를 사용했고, 총 54 task–condition 페어에 대해 각 조건당 10 에피소드(에피소드 최대 24 라운드)를 수집했다. 활성 스킬 수는 실험에서 22개, LLM 백본 기본은 DeepSeek V4-flash를 사용했다.
- 전반적 성능: 표 I 결과에서 AeroWeaver는 9개 태스크 모두에서 평균 에피소드 보상이 가장 높았다. 예시 수치: pursuit-evasion 평균 보상은 AeroWeaver 130.00 ± 4.80, Centralized 90.00 ± 5.00, HMAS-2 70.00 ± 4.60; collection-delivery는 AeroWeaver 49.50 ± 0.68, Centralized 33.91 ± 0.85, HMAS-2 38.70 ± 0.78; world communication은 AeroWeaver 135.00 ± 5.20, Centralized 129.00 ± 5.30, HMAS-2 115.00 ± 0.90. 일부 태스크(예: coverage)는 소폭 개선을 보였음(예: Centralized −14.81 ± 1.02 vs AeroWeaver −14.20 ± 0.95).
- 토큰 비용: Fig. 6에 따르면 AeroWeaver는 9개 태스크에서 HMAS-2 대비 에피소드당 52.0–70.0% 적은 토큰을 소비했으며, Centralized와는 태스크에 따라 토큰 우위가 갈렸다. 보고된 토큰 합계에는 활성화 셋업과 각 라운드 의사결정 호출이 모두 포함됨.
- 성분 기여(애블레이션): 스킬 활성화 비사용, 조정 리포트 비사용, 보상 보정(β=0) 비사용으로 각각 분리 실험을 수행한 결과(표 II), 조정 리포트 비사용이 guided navigation, private communication, world communication, collection-delivery, goal concealment 등 5개 태스크에서 가장 큰 성능 저하를 유발했고, 보상 보정 비활성화는 대체로 가장 덜 해로운 변화였다. 예로 goal concealment에서 조정 리포트 비활성화 시 정규화 점수는 0.605로 크게 하락함(스킬 활성화 비사용 0.777, 보상 비활성화 0.780).
- 추가 실험: (1) 경험-유도 적응: 에피소드 초반 빠른 개선 후 안정화하는 경향을 보였음(그림 7(a)). (2) 백본 민감도: GPT-5.6 Luna·GLM-5.3-Flash는 DeepSeek-V4-Flash 기준에 근접했으나 qwen3.8-flash는 다소 성능 저하를 보임(그림 7(b)). (3) 프롬프트 변형: 의미 보존 재서술·순서 변경보다 무관한 분산(distractor) 삽입이 성능 저하를 더 크게 유발함(그림 7(c)).

## 한계

- 저자 명시 한계: 평가가 사전에 정의된 스킬 카탈로그와 시뮬레이션 실행 조건에서 수행되었고(문장: "The current evaluation is conducted with a predefined skill catalog and simulated execution conditions."), 실제 물리 UAV 플랫폼에서의 검증, 장기 경험 재사용과 광범위한 태스크 전이가 향후 과제로 남아 있음.
- 본문에서 확인되는 제약(논문 본문 근거): (1) 메모리 검색은 동일 태스크·역할의 정확 매칭 후 자카드 유사도로 상위 32개를 취해 일반화가 제한될 수 있음(III-C). (2) 실험은 AirSim 시뮬레이터, 22개 스킬, 고정 상대 정책, 최대 24 라운드 에피소드 등 제한된 조건에서 수행되어 현실환경 잡음·통신 손실·하드웨어 제약을 충분히 다루지 않음(IV-A). (3) 온라인 적응은 모델 파라미터나 저수준 컨트롤러를 변경하지 않는 보정 방식이므로 표현적 한계 및 장기적 수렴성에 대한 검증이 부족함.
- 추가 관찰(본문 근거): 토큰 비용은 HMAS-2 대비 절감 효과가 크지만 Centralized 대비 이점은 태스크에 따라 달라 서비스 비용·확장성 측면의 트레이드오프가 존재함(IV-B, Fig. 6).

## 개발자 관점

- 재현을 위해 논문 본문에 제시된 핵심 구현 요소를 준비할 것: 스킬을 기술하는 skill.md 문서(이름·설명·입출력·운영조건·실행자·의존성), 액티베이션 파이프라인(미션 파싱→At 검색→TopK로 Lk 생성), 각 에이전트의 역할-조건화된 프롬프트와 로컬 컨텍스트 구조를 동일하게 구성해야 함(III-A, III-B).
- 온라인 보정 구현 세부: 선택기에서 최대 20 대안 점수를 요청하고, 메모리는 태스크·역할 정확 매칭 후 자카드 유사도로 상위 32개를 취함. 반환은 에피소드 내 가중치 없는 평균으로 계산하며 식(4)·(5) 기반으로 z' = z + β bA를 적용(III-C). 실험 파라미터 γ=0.95, β=0.8가 본문에서 사용됨(IV-A).
- 배포·운영 관점: AeroWeaver는 중앙 에이전트가 모든 행동을 합성하지 않고 바디-로컬 에이전트들이 실행하므로 분산 실행 환경에 적합하나, 에이전트별 LLM 호출·활성화 셋업(토큰 비용)이 시스템 총비용에 영향. 토큰 비용 최적화를 위해 스킬 활성화로 로컬 컨텍스트를 축소하는 전략을 활용해야 함(IV-B, Fig. 6).
- 안전성·신뢰성: 무효 호출 시 자기 바디 정지 처리가 되어 있어 기본 안전 장치가 있으나, 입력 메시지(동료 메시지)가 다음 라운드 로컬 컨텍스트로 들어감으로써 악의적·오염된 메시지에 대한 검증/필터링(신뢰도·출처 확인) 메커니즘을 설계하는 것이 권장됨(III-B).
- 로깅·디버깅: 역할-인덱스 경험 기록(ρ, s, σ, a, r, G)과 출처 정보(기체·트래젝토리 ID)를 상세히 보관하면 온라인 보정의 원인 분석과 이력 기반 회귀 진단에 필수적임(III-C).
