## 한 문장 요약

법률 질의응답에서 각 주장마다 인용 근거를 검증하는 두-에이전트 시스템 GANDR를 제안하고, 각 주장 단위의 엄격한 검증 기준과 감사 추적을 도입해 엄격 정확도(strict accuracy)를 크게 향상시켰다.

## 해결하려는 문제

기존의 근거 기반(grounded) 생성 파이프라인은 답변 전체를 통합적으로 점수화하므로 정답 결론이 허구 또는 부정확한 인용에 의존해도 높은 점수를 받을 수 있다. 고위험 도메인(예: 법률)에서는 사용자가 시스템이 인용한 출처로부터 각 주장을 직접 검증할 수 있어야 하며, 이를 위해서는 주장 단위의 검증을 수행하는 시스템과 이를 측정하는 엄격한 평가 기준이 필요하다.

## 핵심 기여

- 주장 단위의 감사(audit)를 수행하는 두-에이전트 구조 GANDR(드래프터(Drafter)와 크리틱(Critic))를 제안하여 각 주장에 대해 인용된 출처와 대조한 감사 추적을 생성함.
- 모든 인용이 검색기가 반환한 구절(passage)에 대응해야 한다는 엄격한(strict) 정답 기준을 도입해 인용-주장 대응을 강제함.
- 동일한 백본(backbone), 동일한 검색 표면(retrieval surface), 동일한 인용 지침을 공유하는 6개 시스템 비교에서 GANDR가 주요 지표에서 최고 성능을 기록함(185문항 벤치마크에서 엄격 정확도 70.8%).
- 프로토콜에 기반한 'commit' 규칙이 성능 개선의 핵심임을 보이고(해당 규칙을 되돌리면 엄격 정확도가 22.7점 낮아짐), 성능 향상이 드래프터 구성과 프로토콜 기반 커밋에 기인함을 분석함.
- 크리틱의 감사가 법률 훈련을 받은 두 명의 주석자와 비교해, '근거가 부족한 주장'을 이진 검출기로서 F1 0.84로 식별함을 보고함(다만 4분류(4-way) 판정은 약하게 일치하여 자문(advisory) 수준임).

## 접근 방법

* 논문은 두 에이전트(GANDR)를 제안한다.
* Drafter는 구조화된 법률 추론 형식으로 답변을 작성하고 각 주장에 인용을 달며, Critic은 검증자와 동일한 정보(같은 검색 결과·인용 지침)를 가지고 각 주장을 해당 인용 출처와 대조하여 주장의 근거 여부를 판정하고 주장별 감사 추적(audit trace)을 반환한다.
* 시스템은 '엄격한' 정답 기준을 채택하여, 모든 인용이 반드시 검색기가 반환한 어떤 구절로 해석(resolve)되어야만 유효하다고 본다.
* 논문은 또한 'protocol-anchored commit' 규칙을 도입해 크리틱의 감사 결과에 따라 드래프터의 주장·인용을 확정(commit)하는 절차를 운영하며, 이 규칙이 성능 향상에 핵심적임을 실험적으로 보여준다.
* (본문에서 제시된 구현·학습·하이퍼파라미터 세부사항은 제공된 자료에서 확인되지 않음.)

## 주요 결과

- 데이터셋/규모: 185개 항목(법률 벤치마크).
- 비교 설정: 6개 시스템이 동일한 모델 백본과 동일한 검색 표면, 동일한 인용 지침을 공유하는 통제된 실험.
- 주요 수치: GANDR가 엄격 정확도(strict accuracy) 70.8%를 기록하여 가장 높은 성능을 보였음. 가장 강한 베이스라인 대비 선두 격차는 +11.3 포인트(p < 0.01).
- 아블레이션: 프로토콜 기반 커밋 규칙을 제거(되돌림)하면 엄격 정확도가 22.7 포인트 하락함.
- 백본 변형: 추가로 실험한 세 가지 다른 백본에서도 GANDR의 엄격 정확도 선두는 유지되어 +3.2에서 +6.5 포인트의 우위를 보였음(세부 백본 이름·수치는 본문에서 확인되지 않음).

## 한계

- 저자 기재 한계(논문 본문 근거): 크리틱의 4분류(4-way) 판정은 약하게 일치하여 권고(advisory) 수준이며, 완전한 자동 판정의 대체가 아님.
- 저자 기재 한계(논문 본문 근거): 코드가 '요청 시 제공' 형식으로 공개되어 있어 즉시 공개된 재현자원은 제한적임.
- 추론적 제약(문서 기반 확인): 제시된 평가가 185문항 규모의 법률 벤치마크에 국한되어 있어 다른 도메인·대규모 실세계 배포에서의 일반화 가능성은 본문에서 직접 검증되지 않음.
- 추론적 제약(문서 기반 확인): 실험은 동일한 검색 표면과 인용 지침을 공유하는 통제된 비교로 설계되었으나, 실제 검색기 성능·코퍼스 변화에 따른 민감도는 본문에서 상세히 보고되지 않음.

## 개발자 관점

- 재현: 논문은 동일 백본·동일 검색 표면·동일 인용 지침을 엄격히 통제한 비교를 수행했으므로, 재현하려면 논문에서 사용한 검색기·코퍼스·인용 템플릿·백본 정보와 프로토콜 기반 커밋 규칙의 정확한 구현을 확보해야 함. 다만 본문에서 코드가 즉시 공개되지 않아 저자에게 요청하거나 추가 자료가 필요함.
- 구현: 주장 단위의 감사(크리틱)와 드래프터 간의 인터랙션, 그리고 'commit' 절차를 엔지니어링적으로 안정적으로 구현하는 것이 핵심이며, 감사 추적을 구조화해서 로그·증빙으로 남기는 설계가 필요함.
- 배포·비용: 주관찰자(크리틱)가 매 주장마다 출처 대조를 수행하므로 검색 비용과 모델 호출 횟수가 증가해 연산 비용(토큰·API 호출)이 높아질 가능성이 있음. 실서비스화 시 비용-지연(trade-off)을 고려해야 함.
- 안전성: 주장별 검증과 엄격한 인용 대응 규칙은 허위 인용과 환상을 줄여 신뢰도를 높이나, 크리틱의 4분류 판정이 완전치 않으므로 인간 검토자와의 협업 설계를 권장함(크리틱은 보조적·감사적 역할로 배치).
- 데이터·평가: 엄격(strict)한 정답 기준은 실제 검증 가능성을 높이지만, 검색 오류·코퍼스 누락으로 인한 위양성(false negative)이 발생할 수 있으므로 검색기 개선과 회복 전략(예: 대체 근거 제시)을 설계해야 함.

**근거 범위:** 이 분석은 제공된 논문 본문(추출 실패로 제공된 초록 텍스트)을 기반으로 작성되었음. 본문 전체(실험의 상세 설정, 백본·검색기 명시, 구현 세부사항 등)를 직접 확인하지 못해 일부 구현·실험 세부사항(예: 백본 이름, 하이퍼파라미터, 전체 코드 공개 여부)은 본문에서 추가 확인이 필요함. 제시한 모든 수치와 주장은 제공된 텍스트(초록)에 명시된 내용에 근거함.
