## 한 문장 요약

일반 목적의 Gemini 4 Argon 코딩 에이전트 4명(플레이어)과 1명(옵저버)을 Mineflayer로 연결해, 에이전트들이 직접 JavaScript 프로그램을 작성·실행·공유하며 협업해 무작위 생성된 Easy 난이도 생존 월드에서 27시간 14분 만에 엔더 드래곤을 격파한 사례를 보고한다.

## 해결하려는 문제

장기적(하루 이상)이고 수천 단계에 걸친 의존적 작업을 다수의 범용 코딩 에이전트가 계획·코드·디버그·협업만으로 지속적으로 수행할 수 있는지 검증하는 문제다. 기존 연구들은 픽셀·키보드/마우스 제어, 게임 전용 스킬 라이브러리·커리큘럼·사전 작성된 도구 또는 대량의 게임 플레이 데이터에 의존하는 경우가 많았고, 인간이 설계한 게임 전용 로직 없이 범용 코딩 에이전트들이 자율적으로 끝까지 게임을 완료할 수 있는지를 묻는다.

## 핵심 기여

- 범용 코딩 에이전트(Gemini 4 Argon) 4명이 Mineflayer API만으로 협업해 엔더 드래곤을 엔드 투 엔드로 처음 자율 완료한 단일 실행 기록을 상세히 기술함.
- 에이전트 아키텍처·인터페이스(코드로 행동하는 방식), 팀 협업(게임 채팅과 공유 메모리), 도구 재사용과 롤 분화 같은 실제 동작 사례와 전략(예: 엔더 크리스탈 파괴용 흙 쌓기, 엔더 아이 삼각측량)을 문서화함.
- 세션 전체(2,783 프로그램, 63,313개 서로 다른 JS 라인, 229개의 채팅 메시지, 605번의 죽음 등)와 중간 분석(프로그램 중앙값 실행 시간, 에러율, 사망 원인 등)이라는 정량적 로그를 공개하고 검증 절차(옵저버·서버 로그)를 설명함.
- 에이전트가 환경과 상호작용한 인터페이스 제약(프로그램은 파일 생성/프로세스 시작/네트워크 호출 불가, 전역 객체로 상태 유지 등)과 운영 세부(서버가 5분마다 저장, 6번 재시작 등)를 명시해 재현성·안전성 관점의 설계 결정을 공유함.
- 비용·계산량 추정(대략 1.35B 입력 토큰, 약 24k 모델 호출, 토큰 기반 비용 추정)을 제시해 실험의 자원 요구를 구체화함.

## 접근 방법

* 각 플레이어는 Gemini 4 Argon 인스턴스로, Mineflayer와 그 pathfinding 플러그인을 사용해 게임 서버에 연결된다.
* 에이전트는 '행동' 대신 짧은 JavaScript 프로그램을 작성·제출하고(비동기 함수 본문으로 실행), Mineflayer가 반환하는 텍스트(위치·체력·인벤토리·탐지된 객체·에러 로그 등)를 읽어 다음 프로그램을 작성한다.
* 각 프로그램은 에이전트가 선택한 타임아웃(기본 60s)까지 실행되며, 전역 객체에 저장한 상태와 도우미 함수는 프로그램 간에 유지된다.
* 에이전트들은 개인 메모리와 팀 공유 메모리를 갖고, 채팅을 통해 좌표·경고·교훈을 주고받는다.
* 또한 옵저버 에이전트가 세션을 모니터링해 기록을 검증하고 사양 게임(cheating) 여부를 확인한다.
* 실험 환경은 Minecraft Java Edition 1.20.4, 생존 모드, Easy 난이도, 무작위 시드이며, 서버 명령(cheats) 불가, 프로그램은 파일쓰기·네트워크 호출·프로세스 시작 불가.
* 에이전트는 도구 검사·재사용 가능한 도구 구축·작업 검증·메모 기록 등 일반적 소프트웨어 작업 지침을 따름.

## 주요 결과

- 전체 실행: 첫 프로그램부터 엔더 드래곤 격파까지 27시간 14분(2,783개 프로그램 실행, 승리 전 2,783개 중 승리 직전까지의 수치 표기), 63,313개의 서로 다른 JavaScript 코드 라인 기록, 팀 채팅 229건, 총 605회 사망.
- 프로그램 동작 통계: 각 프로그램 중앙값 실행 시간 33.5초, 플레이어 당 프로그램이 약 40% 시간 동안 실행됨, 세션 중 22%의 프로그램이 에러로 종료(본문에서 명시된 수치).
- 모델/토큰/호출량 및 비용(논문 추정): 약 1.35B 입력 토큰(컨텍스트 캐시로 91% 제공), 약 16M 출력 토큰(그중 4M은 '생각' 토큰), 약 24,000 모델 호출. Gemini 4 Argon 공개 목록가 기준 추정 비용: 플레이어들만으로 약 $520(또는 표준가 $1,040), 옵저버와 전후 활동 포함 약 $810(또는 표준가 $1,620). 저자는 이 비용을 '리스트 가격 기반 추정'이라 명시함.
- 중요 타임라인/성과 지점: 돌 도구(+0h06), 철 도구(+0h14), 네더 포털(+1h42), 네더 요새 발견(+2h57), 엔더 펄 확보(+3h06), 블레이즈 로드(+4h17), 엔더 아이 확보(+10h43), 스트롱홀드 위치(+13h17), 엔드 진입(+13h33), 마지막(10번째) 크리스탈 파괴(+26h34), 드래곤 사망(+27h14).
- 사망 원인(서버 로그 기준, 승리 전 605회): 몬스터 351, 드래곤 69, 익사 67, 추락·공허 57, 용암·화염 47, 기타 14(본문 표).

## 한계

- 저자 명시한 한계 — Mineflayer가 제공하는 정밀한 텍스트 기반 관찰: Mineflayer는 블록·엔티티·드래곤 내부 상태 등 인간이 직접 보기 힘든 정보를 텍스트로 제공하며, 에이전트는 이 정보를 사용해 플레이함. 따라서 픽셀-키보드/마우스 기반 플레이(예: SIMA 2)가 더 어려운 과제로 남음.
- 저자 명시한 한계 — 난이도와 prior knowledge: 실험은 Easy 난이도에서 수행되어 몬스터가 주는 피해가 적고 배고픔으로 인한 사망이 없음. 또한 Gemini 4 Argon은 훈련 데이터에서 Minecraft·Mineflayer 관련 지식을 이미 갖고 있을 가능성이 있어 '완전 무지' 환경은 아님.
- 저자 명시한 한계 — 실패와 인프라: 605회 사망, 약 22%의 프로그램 오류, 엔드 전투에 거의 14시간 소요, 서버가 6회 재시작(약 20분 정지 누적)되었다는 점을 저자가 인정함.
- 저자 명시한 한계 — 단일 실행: 논문은 단일 런(저자들이 시도한 첫 실행)을 기술하므로 성공률·재현성에 대한 통계적 일반화가 불가하다고 저자가 명시함.

## 개발자 관점

- 재현 요소: 동일한 재현을 위해선 Gemini 4 Argon(혹은 동등한 코딩 능력의 모델), Mineflayer(및 pathfinding 플러그인)로 구성된 에이전트-서버 인터페이스와 에이전트별 코드 실행 클라이언트(타임아웃, 표준 출력/로그 수집)를 마련해야 한다. 논문은 프로그램이 파일 쓰기·네트워크·프로세스 시작을 못하도록 제약한 점을 구체적으로 보고함.
- 상태·도구 관리: 에이전트들이 전역 객체와 공유 메모리를 활용해 146개의 상태·코드 항목(그중 42개 도우미 함수)을 유지했고, 흔히 쓰이는 헬퍼가 수백 프로그램에서 재사용되었으므로 지속적 상태 보존과 버전 관리(워크스페이스, 버전컨트롤)가 중요하다.
- 모니터링·검증: 옵저버 에이전트와 서버 로그(채팅, 데스, 어드밴스먼트, 전체 프로그램/출력 보관, 월드 5분 저장)를 통한 실시간/사후 검증 설계가 필요하다. 연구팀은 옵저버와 수동 로그 리뷰로 사양 게임·조작을 확인했다고 보고함.
- 인프라·복원력 대비: 서버 재시작(6회, 총 ~20분)과 아이템 소멸(데스 시 드랍 항목) 등으로 인한 손실을 처리하기 위한 회복 전략(아이템 회수, 공동 창고, 긴급 메시지 패턴)을 설계할 필요가 있다.
- 비용·스케일: 보고된 토큰·호출량(약 1.35B 입력 토큰, 24k 모델 호출)과 추정 비용(대략 $520–$1,620 범위)은 프로덕션화·반복 실험을 계획할 때 예산 견적의 출발점이 된다. 대규모 장시간 런은 비용·쿼터·모니터링 부담을 동반함.
