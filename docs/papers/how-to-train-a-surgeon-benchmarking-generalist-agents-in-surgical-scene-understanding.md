## 한 문장 요약

공개 수술 영상·주석을 통합한 진단 벤치마크(SurgKnowBench)와 도구 기반 에이전트 환경(SurgAgentGym)을 만들어 일반 목적 MLLM의 무학습(제로샷) 수술 장면 이해 능력을 진단하고, 에이전트형 추론(도구 호출·지식 검색·시각 그라운딩)이 어떤 과제를 개선하는지 평가했다.

## 해결하려는 문제

일반 목적 멀티모달 대형언어모델(MLLM)이 수술 장면 이해에서 어느 수준의 능력을 갖추었는지 불명확하고, 수술 데이터의 희소성과 평가 프로토콜의 단편성 때문에 제로샷 능력과 도구 기반 추론이 현실적 대안이 될지 평가하기 어렵다.

## 핵심 기여

- SurgKnowBench: 공개 수술 데이터셋 11개(7개 수술 절차·7개 과제 축)를 통합·조화해 376,602 샘플(테이블 표기 총합)·952 단위(테이블 표기)를 포함하는 진단용 벤치마크를 제시하고 17개 MLLM의 제로샷 성능을 평가함.
- SurgAgentGym: 일반 목적 MLLM 에이전트를 위한 에이전트적 환경을 설계하고, 폐쇄·출처 추적된 수술 지식기반(SurgWiki)과 일반 목적 시각 그라운딩(perceive(), SAM2 기반)을 도구로 제공해 에이전트 추론을 평가함.
- SurgWiki: 교과서·임상 지침·튜토리얼 동영상·증례기록을 포함한 74,315개의 인덱스화된 지식 청크(37,672 텍스트, 35,951 튜토리얼 비디오, 692 증례)를 구축하고 출처·증빙을 추적함.
- Two-stage evaluation protocol: Stage I(직접 추론)로 MLLM의 제로샷 한계를 맵핑하고, Stage II(에이전트 추론)로 도구 접근이 실시간 추론에서 어떤 개선을 주는지 최종 답안 성과와 궤적(trajectory) 수준에서 분석함.
- 깊이 있는 궤적 분석과 도구·소스별 사용 패턴을 제시하여 실패 원인(질의 생성, 불완전한 증거, 증거 그라운딩)을 규명함.

## 접근 방법

* 논문은 두 단계 평가 체계를 제안한다.
* Stage I에서는 SURGKNOWBENCH로 11개 공개 데이터셋의 원주석을 QA 스타일로 조화(harmonization)하여 세 가지 과제군(공간 인식: 도구 검출·위치화·트리플릿, 시간 추론: 단계·행동 인식, 워크플로우 평가: CVS·기술 숙련도)을 구성하고 17개 상용·오픈 MLLM을 제로샷으로 평가한다.
* 평가지표로는 매크로 F1(분류), F1@0.5(위치화, Hungarian 매칭 포함), 정확도(phase), 평균 절대오차·가중 카파(기술평가) 등을 사용한다.
* Stage II에서는 SURGAGENTGYM을 통해 에이전트가 두 가지 도구를 호출할 수 있게 한다: perceive()는 SAM2(facebook/sam2-hiera-base-plus)를 이용해 클래스-무관(mask) 제안들을 반환하여 시각적 그라운딩을 지원하고 호출 횟수(단일 이미지 2회·다중 프레임 3회) 등 실행 예산을 제한한다; retrieve()는 질의(query), 지식유형(교과·절차·조건 등), 소스타입(교과서·가이드라인·튜토리얼·증례)을 인자로 받아 SURGWIKI에서 증거를 검색하며 소스별 호출 상한(각 소스 최대 2회)을 둔다.
* 에이전트는 반복적으로 도구 호출·관찰·추론을 수행해 최종 답안을 반환하고 환경은 트레이저토리(도구 사용 여부·검색 질의·검색 결과 관련성 등)를 기록해 분석한다.
* 검색 관련 평가는 TREC 스타일 등급 적합성으로 수행하였고, 검색 결과의 관련성 신호는 LLM 심판과 인간 전문가에 대해 AUROC=0.894(LLM judge)·0.817(인간)으로 보고됨.

## 주요 결과

- Stage I(제로샷) 요약: 도구 검출은 대다수 모델이 다수결·무작위 기준을 웃돌지만 절대 성능은 낮아 최고 매크로-F1이 26.1%(Qwen3-VL-32B) 수준이고, 위치화 최고 F1@0.5는 22.7%(InternVL2.5-78B)에 불과함. 트리플릿(⟨도구,동사,대상⟩) 검출은 모든 모델에서 매크로-F1 < 5%로 매우 취약함. 단계(phase) 인식의 데이터셋 평균 정확도는 다수결 기준을 넘기지 못해 절차적 이해가 약함. CVS(critical view of safety) 평가에서는 몇몇 모델이 빈도 높은 등급으로 '다수결 모드(majority collapse)'를 보이며 정확도는 높게 보이나 카파(κ)는 거의 0 또는 음수로, 우연 수준의 합의만 이룸(예: InternVL2.5-8B 정확도 71.2%에 κ=0).
- Stage II(에이전트형 도구 사용) 요약: 도구 기반 추론은 과제별로 성과가 상이함. 전체적으로 도구 설정은 도구 검출과 행동 인식(action recognition)에서 유의미한 개선을 가져옴(도구 검출은 16모델 중 15개 모델에서 향상 보고). 액션 인식은 오픈소스 모델들에서 큰 개선(+4.6 ~ +26.2 매크로-F1 범위, 매칭 실험 표기) 이 관찰되었으나 정밀한 위치화와 워크플로우/숙련도 평가에서는 일관된 이득이 없거나 모델별로 혼재된 영향이 나타남. 예를 들어 전체 에이전트 설정에서도 최고 행동인식 점수는 27.6%로 다수결(30.0%)보다 낮음.
- 검색·그라운딩 진단: retrieve()의 재랭커(리트리버) 관련성 점수는 LLM judge 대비 AUROC=0.894, 인간 전문가 대비 0.817로 비교적 분별력이 있으며, 에이전트는 작업별 소스 선택 패턴을 보임(행동 인식은 튜토리얼 비디오 80.3% 사용, CVS는 교과서·가이드라인 합 80.8% 사용). 그러나 실패 원인은 주로(1) 잘못된 질의 생성, (2) 불완전·오염된 증거에 대한 강건성 부족, (3) 유용 증거를 최종 답안에 제대로 그라운딩하지 못하는 것임.
- 추적 가능한 정량 지표·제약: retrieve() 호출 예산(소스당 최대 2회), perceive() 호출 상한(단일 이미지 2회·다중 3회), 전체 실험 컴퓨트는 약 4,766 A100 GPU·h + 703 A40 GPU·h ≈ 5,470 GPU·h로 보고됨.

## 한계

- 저자 기술 한계(논문 본문 명시): SURGKNOWBENCH는 공개 수술 데이터셋을 조화한 것이므로 절차·기관·카메라 뷰·주석 스키마·과제 정의 등으로 인해 커버리지가 한정된다.
- 저자 기술 한계(논문 본문 명시): SURGWIKI는 폐쇄적이고 출처 추적된 증거 코퍼스이나 상업적·저작권·가용성 제약으로 내용이 제한된다.

## 개발자 관점

- 데이터 및 코드: 조화(harmonization) 코드와 평가 파이프라인은 공개(저작권: CC BY-NC 4.0)하지만 원자료(비디오·데이터셋)는 각 소스 라이선스에 따라 직접 취득해야 하므로 재현 시 데이터 접근 정책 확인이 필수임.
- 지식베이스 설계: 닫힌 출처·증빙 추적(SurgWiki) 및 소스별 호출 예산(각 소스 최대 2회)을 도입해 의료용 에이전트의 근거 추적성과 거버넌스를 확보하는 설계가 필요함.
- 도구와 백본 상호작용: 최적 도구 구성은 백본에 따라 다르므로(예: 어떤 모델은 retrieve() 비활성화가 성능 향상) 배포 전 백본별 도구 구성(ablation) 검증이 권장됨.
- 시각 그라운딩 한계: perceive()로 SAM2 자동 마스크를 사용해도 세밀한 위치화 성능은 낮아(최고 F1@0.5 ≈22.7%) 실제 임상 적용에는 특화된 시각 모델·후처리 필요함.
- 추론·트래젝토리 로깅: 에이전트의 질의·검색 결과·그라운딩 궤적을 기록하면 실패 원인 분석·감사·규제 준수를 위한 근거 제공에 유용함. 설계 시 로그 구조와 개인정보·저작권 관리 필요함. 또한 검색 관련 재랭커의 신뢰도(AUROC 등)를 모니터링해 에이전트 의사결정에 가중치를 둘 수 있음.

**근거 범위:** 분석은 제공된 논문 PDF 본문(주요 본문, 표, 부록 인용 포함)에 근거하여 작성되었음. 본문과 표에서 명시된 수치(예: 샘플 수, 모델 수, 성능 수치, AUROC, 도구 호출 예산, 컴퓨트 시간 등)를 그대로 인용했다. 부가적 세부 구현(소스의 전체 목록, 내부 인덱싱 파라미터, 학습 파라미터 등)은 본문에 제한적으로 기술되어 있으므로 해당 항목은 원문 표·부록을 참고해야 하며, 본 요약에 없는 내부 실험 세부는 재구성하지 않았음을 밝힌다.
