## 한 문장 요약

연속적인 자연어 업데이트로 변화하는 실제 운영 제약을 다루기 위해 언어기반 문제 구성, 수학적 프로그래밍, 진화적 탐색을 결합하고 최적화 프로그램·수용된 계획·후보해를 메모리로 유지하여 문제를 갱신하는 MAPLE 에이전트를 제안한다.

## 해결하려는 문제

실제 운영 환경은 수요·자원·우선순위가 지속적으로 변하며, 도메인 담당자는 제약을 잘 알지만 운영연구(optimization) 전문 지식이나 전담 지원이 없을 수 있다. 기존 LLM 기반 최적화 에이전트들은 주로 개별(격리된) 요청을 처리하도록 설계되어 있어, 이후의 빠른 갱신에서 이전에 만들어진 결정들을 보존하거나 유용한 탐색 결과를 재사용하는 데 한계가 있다. 연구 질문은 자연어로 들어오는 연속적·동적 업데이트들에 대해 최적화 문제와 실행 가능한 상태(executable state)를 유지하면서 유효한 갱신을 수행하고 이전 탐색 정보를 재활용하는 방법이다.

## 핵심 기여

- MAPLE (Memory-Augmented Planning with Language and Evolution)이라는 에이전트를 제안하여 연속적 자연어 요청을 통한 최적화 문제 유지·갱신을 다룸.
- 언어 기반 문제 구성(Language-to-model)과 수학적 프로그래밍(mathematical programming), 진화적 탐색(evolutionary search)을 결합한 혼합적 접근을 제시.
- 에이전트가 최적화 프로그램(실행 가능한 모델), 수용된 계획(accepted plans), 이전 업데이트 이력, 후보해(candidate solutions)를 메모리로 보존하도록 설계하여 이후 요청에서 재사용할 수 있게 함.
- NLDO라는 벤치마크(15개 궤적/trajectory, 총 180회 업데이트)를 도입하여 선택(selection), 스케줄링, 근무배치(rostering), 라우팅, 클라우드 자원 배치 등 다양한 도메인을 포함한 연속적 갱신 시나리오를 구성.
- 주요 평가에서 모든 궤적을 완료했고 online scalar quality 0.951, Pareto hypervolume ratio 0.875를 달성했으며, 대조 실험에서 실행 가능한 상태를 유지하는 것이 업데이트 유효성(update validity) 개선과 탐색 정보 보존에 기여함을 보였음.

## 접근 방법

* (본문에서 확인 가능한 수준으로 요약) MAPLE는 자연어 요구사항을 최적화 모델 또는 솔버 프로그램으로 변환하는 언어 기반 문제 구성 단계와, 이 모델을 해결하기 위한 수학적 프로그래밍 절차 및 진화적 탐색을 결합한다.
* 핵심적으로 에이전트는 다음 항목들을 메모리로 유지한다: (1) 현재의 실행 가능한 최적화 프로그램(모델/solver 프로그램), (2) 이전에 수용된 계획들(accepted plans), (3) 이전 업데이트들의 이력, (4) 검색 중 생성된 후보해들(candidate solutions).
* 이러한 상태를 보존함으로써 이후의 자연어 업데이트가 들어왔을 때 모델을 갱신하고 수용 가능한 계획을 빠르게 검증·생성하며, 진화적 검색에서 유효한 후보군을 재활용하여 탐색 비용을 줄이려는 구조로 설명된다.
* (구체적 알고리즘, 모델 학습·하이퍼파라미터, LLM 또는 솔버 인터페이스의 구현 세부사항은 본문 초록에만 언급되어 있어 확인 불가.)

## 주요 결과

- 벤치마크: NLDO(15개 궤적, 총 180회 업데이트) — 도메인: 선택, 스케줄링, 근무배치, 라우팅, 클라우드 자원 배치.
- 주요 정량 성과: 모든 궤적을 완료했고 online scalar quality = 0.951, Pareto hypervolume ratio = 0.875를 달성.
- 대조 실험 결과: 실행 가능한 상태(optimization program 등)를 유지하는 접근은 업데이트 유효성(update validity)을 향상시키고, 상당한 수정이 있어도 유용한 탐색 정보를 보존할 수 있음(구체적 수치·베이스라인 비교 표는 본문 초록에 부재).

## 한계

- 저자가 명시한 한계: 초록에는 저자가 직접 언급한 명시적 한계가 포함되어 있지 않음.
- 본문 실험·범위에서 합리적으로 확인되는 한계: (1) 평가가 NLDO(15 궤적, 180 업데이트)로 제한되어 있어 더 큰 규모나 다른 도메인·현장 데이터로의 일반화 가능성은 불명확함, (2) 진화적 탐색 및 상태 저장이 요구하는 계산·메모리 비용과 실시간 적용성(스루풋·지연)에 대한 정보가 제공되지 않음, (3) 언어 기반 변환(자연어→모델)의 신뢰성·오류 사례와 이를 검증·수정하는 절차에 대한 구체적 설명이 초록 기준으로는 제공되지 않음, (4) 구체적 구현(사용한 LLM/솔버/진화연산자 등)과 재현성 관련 세부사항이 불명확하여 재현이 바로 가능하지 않을 수 있음.

## 개발자 관점

- 실행 가능한 최적화 프로그램(executable model)을 버전관리하고 각 업데이트에서 모델·제약·목적함수를 기계적으로 검증할 수 있는 검증 파이프라인이 필요하다.
- 수용된 계획과 후보해를 보존하려면 해(解) 풀(pool)과 메타데이터(유효성 검사 결과, 생성 시점의 제약/데이터 스냅샷)를 함께 저장해야 하며, 이후 갱신 시 재유효성 검사를 자동화해야 실서비스 적용이 용이하다.
- 언어→모델 변환 과정은 LLM 출력의 불확실성을 고려해 자동 검증·인간 검토(또는 제약 기반 검사)를 포함하는 방어적 설계가 필요하다(잘못된 제약 추가 방지, 제약 중복/충돌 감지 등).
- 진화적 탐색을 도입할 경우 후보군 재사용을 위한 인터페이스(입력 포맷, 제약 변경에 따른 적합도 재평가 함수)를 명확히 정의하고, 탐색·검증 비용을 모니터링해 실시간 요구를 충족시킬 수 있는지 평가해야 한다.
- 재현성을 위해서는 NLDO 벤치마크(논문에서 제시한 경우)와 MAPLE의 코드·환경·시드·평가 스크립트를 공개해야 하며, 실험 비용(컴퓨트·솔버 라이선스 등)과 안전성(LLM이 제약을 잘못 생성하는 경우의 실패 모드)을 문서화해야 한다.
