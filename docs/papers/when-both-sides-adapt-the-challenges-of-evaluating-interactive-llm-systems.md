## 한 문장 요약

사용자와 LLM이 상호 적응하는 상호작용 환경에서, 사용자의 프롬프트 분포가 모델 응답에 의해 내생적으로 바뀌는 문제를 수학적으로 모델링해(마르코프·단일턴 가정) 오프라인 벤치마크와 라이브 A/B 테스트가 서로 다른 추정량으로 수렴함을 보이고, 순위 역전 조건·사전검사 휴리스틱·분산 증가 효과를 분석한다.

## 해결하려는 문제

일반목적 LLM 시스템은 사용자와의 다중 턴 상호작용에서 ‘양측 적응성’이 존재한다. 사용자는 모델 응답을 관찰한 뒤 다음에 어떤 과제(프롬프트 유형·난이도·프롬프트 전략)를 시도할지 바꾸며, 이로 인해 모델을 평가할 때 실제로 측정되는 프롬프트 분포가 모델에 따라 달라질 수 있다. 기존의 오프라인 벤치마크(고정 프롬프트 분포)와 라이브 A/B 테스트(사용자-모델 상호작용으로 유도된 분포)는 서로 다른 양(target estimand)을 측정할 수 있고, 이로 인해 모델 순위·배포 결정·통계적 분산 추정이 달라질 수 있다는 문제가 있다.

## 핵심 기여

- (모델링) 사용자 프롬프트와 모델 응답 간 피드백을 포함하는 확률적 상호작용 프레임워크를 제시하고, 해석 가능성을 위해 ‘단일 턴(마르코프) 의존’ 가정(Assumption 1,2)과 장기수렴 가정(Assumption 3)을 도입했다.
- (추정량 정의) 두 종류의 비교 추정량을 명확히 정의: 공통분포 효과(τ_common, 같은 프롬프트 분포에서의 성능 차)와 유도분포 효과(τ_induced, 각 모델이 유도한 프롬프트 분포에서의 성능 차).
- (추정량 대응) 표준 차등-평균(difference-in-means) 추정량이 오프라인 벤치마크에 대해서는 τ_common으로, 사용자 시뮬레이션·A/B 테스트에 대해서는 τ_induced로 수렴함을 증명(Prop.1).
- (순위 불일치·휴리스틱) τ_induced를 τ_common과 분해(식(17))해 순위 역전이 발생하는 조건을 유도하고(lemma), 순위 일치 보장을 위한 충분조건(Prop.3, 부등식(19))과 이를 활용한 오프라인 사전검사 휴리스틱(Algorithm)을 제시.
- (분산 분석) 단순 선형 AR(1) 스타일 모형으로 사용자·모델 적응 민감도(γ_P, γ_M)의 곱에 따라 추정량 분산이 크게 증가할 수 있음을 분석: γ_Pγ_M<1이면 분산 상수 인플레이션, γ_Pγ_M=1이면 분산이 Θ(T)로 증가, γ_Pγ_M>1이면 분산이 지수적으로 증가함을 보임(Prop.5).

## 접근 방법

* 논문 본문 기준: (1) 사용자와 모델을 각각 프롬프트 공간 P와 응답 공간 R를 가지는 확률적 커널 Q_user(·\|history)와 Q_model(·\|prompt; M)로 모델링한다.
* (2) 주된 단순화로 '단일 턴 의존'을 가정해 다음 프롬프트는 직전 모델 응답에만 의존(Assumption 1), 모델 응답은 현재 프롬프트에만 의존(Assumption 2)하도록 설정한다.
* (3) 각 턴 t에서 모델 M이 유도하는 프롬프트 마진 π_t(M)과 장기분포 π(M) 가정을 둔다(Assumption 3).
* (4) 성능은 턴 수준(metric Y^k_it(p;M))의 기댓값 µ^k(M,π)=E_{p∼π}[E[Y\|p;M]]로 정의하고, 두 추정량 τ_common(π)=µ(M1,π)−µ(M0,π)과 τ_induced(e)=µ(M1,π^e(M1))−µ(M0,π^e(M0))를 도입한다.
* (5) 표준 difference-in-means 추정량을 각 평가절차(bench, sim, human)에 적용하여 수렴 대상이 서로 다름을 보인다(Prop.1).
* (6) τ_induced를 τ_common(π(M0))와 구성(composition) 효과로 분해(식(17))해 순위 역전 조건을 도출하고, 총변이(TV)와 M1의 성능 범위로 구성효과를 상계해 충분조건(부등식(19))을 제시한다(Prop.3) — 이로부터 오프라인 사전 검사 알고리즘을 제안한다.
* (7) 추가로 단순화된 선형 동역학 모델(P_{t+1}=α_P+γ_P R_t+ν, R_t=α_M+γ_M P_t+ϵ, Y linear in R)으로 피드백 강도 ρ=γ_Pγ_M에 따른 분산 거동을 정량화하고 세 구간(ρ<1, ρ=1, ρ>1)에서의 스케일링을 유도(Prop.5).

## 주요 결과

- 추정량 수렴(Prop.1): 오프라인 벤치(drawn from π_bench)의 difference-in-means 는 확률수렴하여 τ_common(π_bench)으로, 사용자 시뮬레이션·A/B 테스트의 difference-in-means 는 τ_induced_{1:T}(e)로 수렴. 시간이 가면 τ_induced_{1:T}→τ_induced(e) (Assumption 3 하).
- 모형적 예제(Example 1, 이메일 작성): 초기 턴에서 두 모델 M0,M1은 모두 첫 턴 성공률 90%를 보이나(0.9), 두 모델의 두 번째 턴 기대 성공률은 M0 = 83.3%(계산: (80·0.9+10·0.3)/90), M1 = 72.2%((10·0.9+80·0.7)/90). 전체(두 턴) 집계 성능은 M0=86.65%, M1=81.1%로 M0가 유리해 순위 역전 발생(논문 계산). 두 턴 induced-distribution 비교에서 τ_induced_{1:2}(human) = −0.0555로 표기됨.
- 순위 역전 분해(식(17)) 및 충분조건(Prop.3): τ_induced = τ_common(π(M0)) + Σ_{cells S∈S_Y(M0)×S_Y(M1)}[π(S;M1)−π(S;M0)]·µ(S;M1). 순위 일치는 |τ_common(π(M0))| ≥ TV_{P_Y}(π(M1),π(M0))·(max_S µ(S;M1)−min_S µ(S;M1)) 라는 쉬운 상계로 보장(식(19)). 이로부터 오프라인 사전검사 알고리즘(알고리즘 4)을 제시: (1) 기준분포 설정, (2) τ_common 평가, (3) 이전 배포 데이터로 TV 추정, (4) M1 성능 범위 대략 추정, (5) 부등식(19) 평가.
- 분산 거동(Prop.5): 선형 예시에서 사용자 적응이 없을 때(γ_P=0) 시간평균 분산 V_T(0)=b_k^2(γ_M^2 σ_P^2 + σ_M^2)/T. 사용자 적응(γ_P>0)이 있을 때 비율 V_T(γ_P)/V_T(0)는 세 경우로 구분됨: (i) 0≤γ_Mγ_P<1: 계수 1/(1−γ_Mγ_P)^2로 상수 인플레이션(1+O(1/T)); (ii) γ_Mγ_P=1: 분산은 Θ(T) (정확히 ∝ T^2/3 ·(1+o(1))); (iii) γ_Mγ_P>1: 분산은 지수적으로 증가(Θ((γ_Mγ_P)^{2T}/T)). 논문은 이를 통해 충분한 표본수·시계열 길이 고려 필요성을 제시.
- 추상적·실천적 시사점: 사용자 적응은 '보상 해킹'(aggregate metric 개선을 위해 쉬운 프롬프트로 유도), '노벨티(신규성) 효과'와 관찰·해석 문제를 동일한 메커니즘으로 설명함. 또한 벤치마크 재생(replay) 방식은 τ_common을 측정하므로 배포시 실질적 성능(τ_induced)을 보장하지 못할 수 있음.

## 한계

- 저자 명시: 모델의 주요 결과들은 분석의 추론 가능성을 위해 단일턴(마르코프) 의존 가정(Assumptions 1–2)과 대화 간 독립(사용자 간 상호학습 무시)을 가정함. 이 가정은 실제 장기·상호 사용자 학습 상황에서 위배될 수 있다고 저자도 명시함.
- 저자 명시: 선형 동적 모형은 매우 단순한 장난감(역설적) 모형이며 LLM-사용자 상호작용의 고차원·비선형 특성을 포착하지 못함(저자도 이 점을 한계로 명시).
- 저자 명시: 실증적 검증·데이터 실험이 제공되지 않음 — 논문은 이론·모형 분석 중심으로, 실제 사용자 로그·시뮬레이터의 갭(sim2real) 문제는 별도 연구가 필요함.
- 본문에서 확인되는 추가 한계(분석적 제약): 실무적 휴리스틱(식(19))은 적절한 프롬프트 분할 S_Y의 구축과 각 셀 수준 성능 추정에 의존함. 본문도 언급하듯 고차원 프롬프트 공간에서는 세분화된 파티셔닝이 어렵고 민감도 분석이 필요함(실무적 비용·복잡도).

## 개발자 관점

- 실험 전(오프라인) 사전검사: 논문 Algorithm을 따라 τ_common(π(M0)), 이전 배포에서의 총변이(TV) 추정치, M1의 셀별 성능 범위(upper/lower)를 구해 부등식(19)을 확인하면 오프라인 평가가 A/B 결정을 대체 가능한지 판단할 수 있다.
- 평가 리포트 권장사항: A/B 결과뿐 아니라 프롬프트 구성(p prompt composition), 셀별(과제 유형별) 성능 및 시간별(턴별) 분포 변화를 함께 보고해야 유도된 분포 효과·보상 해킹 여부를 진단할 수 있다.
- 실험 설계: 사용자 적응이 예상되면 표본크기·실험 기간을 늘려야 하나 γ_Pγ_M(사용자×모델 민감도) 값에 따라 분산이 급격히 증가할 수 있음 — 사전 민감도 추정이 없으면 보수적 표본 산정과 민감도 기반 시나리오 분석을 수행할 것.
- 번업·번인 전략 신중 적용: 초반 burn-in 제거는 '공통프롬프트 성능'을 측정하려는 목적에는 역효과(공통 부분 관찰 제거)를 낳을 수 있으니 실험 목적(단기 vs 장기 성능)을 사전에 명확히 해야 함.
- 배포 안전·정책: 모델 배포는 프롬프트 분포 자체를 바꿀 수 있으므로 안전 지표(예: 사고 발생 프롬프트 비중)도 유도분포 관점에서 모니터링해야 함 — 오프라인 리플레이 안전평가만으로는 부족할 수 있음.
