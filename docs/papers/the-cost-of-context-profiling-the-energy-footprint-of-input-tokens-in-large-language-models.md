## 한 문장 요약

LLM의 프리필(prefill) 단계에 대한 고해상도 GPU 텔레메트리(1ms NVML 샘플링)와 로그 스케일 컨텍스트 스윕을 통해 입력 토큰의 에너지 스케일링 법칙과 SDPA(HF) 대비 vLLM(PagedAttention)의 임계점 지연 및 에너지 이득을 규명한다.

## 해결하려는 문제

기존 추정법은 출력 토큰 기준으로 추정하며(특히 API 기반 접근), 하드웨어 수준의 전력 급증과 시스템 수준의 총 에너지에 대한 ‘프리필 패러독스’(하드웨어 전력 스파이크는 크지만 총 에너지는 입력 토큰에 대해 거의 증가하지 않음)가 존재한다. 본문은 (1) 언제 self-attention의 O(n^2) 복잡도가 GPU 병렬화 이점을 압도하는지, (2) 메모리 오케스트레이션 전략(PagedAttention vs SDPA)이 이 임계점을 어떻게 이동·안정화하는지, (3) 컨텍스트 깊이에 따라 입력(프리필)과 출력(디코드) 토큰 간 에너지 강도 비율이 어떻게 변화하는지라는 구체적 연구 질문을 제시한다.

## 핵심 기여

- 고해상도 GPU 텔레메트리(NVML 1ms 샘플링)와 로그 스케일 컨텍스트 스윕을 결합한 벤치마크 방법론으로 프리필/디코드 단계를 분리·정량화함.
- HF Baseline(SDPA)와 vLLM(PagedAttention)을 비교해 PagedAttention이 32k 수준까지 고효율 병렬단계를 유지하며 O(n^2) 병목을 지연시키는 것을 실증함.
- 112,000 토큰 지점에서 Llama-3.1 기준 vLLM이 HF Baseline 대비 약 7.6×(Qwen-2는 최대 8.9×)의 에너지 효율 우위를 보이는 정량적 결과를 제시함.
- 입력 토큰 대비 출력 토큰의 에너지 강도 비율(𝐸_out/𝐸_in)을 엔진별로 규명: 최적화된 엔진(vLLM)은 1k에서 ≈850×→112k에서 ≈750×로 격차가 좁아지며, 비최적화 엔진은 대략 150–230× 범위로 비교적 평탄함을 보임.
- 전력-지연(평균 전력 vs ms/토큰) 위상도를 통한 'Compute Saturation Cliff' 개념을 도입해, 전력 포화(≈280–310W) 이후 지연 증가가 에너지 강도의 주요 원인임을 밝힘.

## 접근 방법

* 실험은 NVIDIA A100(80GB)에서 Llama-3.1 8B 및 Qwen-2 7B(둘 다 bfloat16)로 수행되었고, NVML을 통해 1ms 간격으로 GPU 전력을 샘플링했다.
* 입력은 고엔트로피 기본 텍스트를 반복하여 토크나이저(모델 고유 토크나이저)를 이용해 정확한 길이 L∈[2^8, 2^17]로 잘라내는 로그 스케일 컨텍스트 스윕을 사용했다.
* 두 엔진을 비교: (1) HF Baseline(Scaled Dot-Product Attention, 연속 KV 캐시), (2) vLLM(Optimised, PagedAttention + FlashAttention 커널 퓨전).
* 프리필은 생성 길이를 1로 설정해 prefill_start~prefill_end 구간의 전력 적분으로 𝐸_prefill을 계산했다.
* 추가로 출력 길이 G=128 고정 실험을 통해 전체 에너지에서 𝐸_prefill을 빼서 평균 출력 토큰 에너지 𝐸_out을 추정하고, 𝐸_out/𝐸_in을 비교했다.
* 결과 해석을 위해 평균 전력과 정규화된 레이턴시(ms/토큰)의 상관 분석을 수행해 단계(High Parallel Efficiency, Compute Saturation Cliff, Memory Bandwidth Wall)를 식별했다.

## 주요 결과

- 프리필 에너지(𝐽) 및 지연(초) 예시(≈112k 토큰): Llama-3.1 HF Baseline: 25.54s, 7,600.2J, 0.0678J/토큰. Llama-3.1 vLLM: 3.54s, 1,005.1J, 0.0090J/토큰. Qwen-2 HF Baseline: 23.04s, 6,832.0J, 0.0610J/토큰. Qwen-2 vLLM: 2.71s, 769.6J, 0.0069J/토큰.
- 에너지 효율 이득: Llama-3.1에서 vLLM은 HF 대비 약 7.6× 효율(112k 토큰 기준), Qwen-2에서는 최대 8.9×까지 보고됨(본문 표 및 서술).
- 전력·지연 거동: 컨텍스트가 ≳16,384 토큰일 때 GPU 전력은 약 280–310W에서 포화하며(Compute Saturation Cliff), 이 이후에는 전력이 크게 증가하지 않고 레이턴시(ms/토큰)가 늘어나면서 에너지 강도가 증가함(특히 HF Baseline에서).
- 입력 vs 출력 강도: vLLM의 경우 1k 컨텍스트에서 출력 토큰은 입력 토큰보다 ≈850× 더 에너지 집약적이며 컨텍스트가 112k로 증가하면 ≈750×로 격차가 좁아짐. HF Baseline은 대체로 ≈155×→≈220×(모델 및 컨텍스트에 따라 범위 다름)로 비교적 평탄한 비율을 보이며, 이는 Baseline의 프리필 비용이 높기 때문임.
- vLLM은 32k 이상에서야 J/토큰 프로파일이 상승하기 시작하는 반면 HF Baseline은 더 작은 컨텍스트에서 이미 증가 경향을 보이며, PagedAttention·FlashAttention 기반의 메모리 오케스트레이션이 O(n^2) 병목을 수천~수만 토큰 단위로 지연시킴.

## 한계

- 저자 언급: 실험은 GPU(주로 A100) 전력에 초점을 맞추며 CPU/DRAM(RAPL) 텔레메트리는 가상화 환경에서 제한적이라 제외했음(따라서 전체 시스템 에너지가 아닌 GPU 중심 측정임).
- 저자 언급: 본 연구는 텍스트 전용 스택을 대상으로 하며, 멀티모달 입력이나 다른 아키텍처(예: MoE, 70B+ 모델)에 대한 확장성은 향후 작업으로 제안됨(향후 연구 항목으로 배칭 영향, 저정밀도(FP8/INT4) 에너지-정밀도 트레이드오프, 대형 모델 스윕을 제시).
- 실험 범위에서 드러나는 제약: 실험은 A100(80GB) 하드웨어, bfloat16, Llama-3.1 8B와 Qwen-2 7B의 두 모델군에 한정되어 있어 다른 GPU 세대(예: H100), 다른 정밀도나 더 큰 파라미터 모델로의 일반화는 제한적임.
- 실험 범위에서 드러나는 제약: 입력은 반복된 고엔트로피 텍스트로 합성했으므로 실제 응용의 다양한 토큰 분포(예: 멀티모달, 문서 구조, 압축된/희소한 토큰 패턴)가 에너지 거동에 미치는 영향은 본문에서 직접 평가되지 않음.

## 개발자 관점

- 프리필·디코드 단계를 분리해 측정하려면 inference 엔진에서 prefill_start/prefill_end 이벤트를 얻고 NVML 같은 고분해능 전력 샘플링(1ms)을 타임스탬프 정렬해야 한다.
- 긴 컨텍스트를 다루는 서비스에서는 vLLM과 같은 PagedAttention·FlashAttention 기반 엔진 도입이 실운영 전력·에너지 절감에 결정적이며, 특히 컨텍스트가 수만 토큰에 이를 때 큰 효과(수배의 에너지 절감)를 기대할 수 있다.
- 배포 시 A100 수준의 전력 포화(≈280–310W)를 고려해 설계해야 하며, 포화 이후에는 전력 증가보다 레이턴시 증가가 에너지 증가의 주 원인이라는 점을 염두에 둘 것(즉 병렬화 유지가 핵심).
- 재현을 위해서는 모델-고유 토크나이저 사용, 워밍업 패스 수행, 단일 토큰 생성(프리필 고립) 같은 제어 절차를 따라야 하며, 엔진별 컨텍스트 상한(예: vLLM의 모델 선언 컨텍스트 제한)을 확인해야 한다.
- 운영 관점에서는 긴 프리필을 자주 발생시키는 RAG·장문 요약 등 워크로드는 엔진 선택이 인프라 비용(전기비, 냉각비)에 큰 영향을 미치므로, 에너지 기반 비용 모델을 배포 의사결정에 포함할 것을 권장한다.
