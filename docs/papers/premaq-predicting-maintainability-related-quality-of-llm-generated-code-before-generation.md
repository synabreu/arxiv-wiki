## 한 문장 요약

LLM의 입력 처리 중 계산되는 prefill 활성화(pre-fill activations)를 이용해 코드 생성 이전에 생성될 코드의 유지보수 관련 품질(CSS, MI)을 예측하고, 이를 모델 선택에 활용해 더 유지보수성 높은 출력을 확보하는 방법(PreMaQ)을 제안한다.

## 해결하려는 문제

기존 연구는 LLM이 생성할 코드의 기능적 정합성(functional correctness)을 생성 전에 내부 표현으로 예측하는 방법을 보였으나, 유지보수 관련 품질(예: 코드 냄새, 구조적 복잡도)을 생성 이전에 예측할 수 있는지는 불명확했다. 실제 개발 환경에서는 코드 생성·평가 비용이 크므로, 생성 전에 낮은 품질의 출력을 미리 회피할 수 있는 방법이 필요하다. 또한 모델 크기나 단순한 기능적 정합성 예측만으로는 유지보수 관련 품질이 높은 모델을 선택하기에 충분하지 않다(저자 예비 연구 결과: 여러 모델이 기능적으로 정답을 생성하는 경우가 많고 이들 사이에 CSS·MI 차이가 큼).

## 핵심 기여

- LLM의 prefill 활성화(프롬프트 처리 직후의 최종 토큰 위치의 내부 표현)로부터 코드 냄새 점수(CSS)와 유지보수 지수(MI)를 생성 전(prediction-before-generation)에 예측하는 PreMaQ를 제안.
- 네 개의 오픈 웨이트 LLM(DeepSeek-Coder-6.7B-Instruct, Qwen2.5-Coder-7B-Instruct, Phi-4, Qwen3.5-27B-FP8)과 네 개의 파이썬 코드 생성 벤치마크(HumanEval+, MBPP+, BigCodeBench, LiveCodeBench)의 2,695개 태스크로 평가하여, within-benchmark 평균 Spearman ρ가 CSS=0.57, MI=0.65를 달성함을 보임.
- 예측 결과를 모델 선택에 적용하여, 기능적으로 정답을 생성하는 후보들 중에서 유지보수 관련 품질을 높이는 선택이 가능함을 보였고(대상 N=1,534 태스크), PreMaQ 기반 선택은 무작위 대비 유지보수 품질 개선 간극의 59.5%를 닫음.
- 프롬프트 임베딩(black-box)과의 결합이 상호보완적임을 보임: PreMaQ와 프롬프트 임베딩 예측을 결합하면 상대적 이득이 60.7%로 증가함.

## 접근 방법

* 문제정식: 각 LLM f와 벤치마크 D에 대해, 프롬프트 x를 LLM에 포워드할 때 얻는 prefill 활성화 z_f(x)만으로 생성될 코드 f(x)의 품질 지표 q(f(x))를 회귀로 예측한다.
* 입력 특징: 각 Transformer 블록의 최종 토큰 위치의 뉴런 출력(h_ℓ(x))들을 레이어 차원으로 concat하여 a_f(x)를 구성하고, 차원별 z-score 표준화(z_f(x))를 수행함.
* 활성화 원천으로 Attention 출력, MLP 출력, Attn+MLP, residual을 비교하였고 Attention 출력이 가장 성능이 좋음.
* 예측 대상: AvgPassRatio(기능적 정합성; [0,1]), CSS(코드 냄새 점수, [0,10], Pylint 위반 메시지 가중합 기반), MI(유지보수 지수, [0,100], radon으로 계산되는 Halstead, CC, LOC 기반).
* 예측기 아키텍처: 각 (모델 f, 벤치 D, 지표 q) 조합에 대해 MLP 회귀기를 학습(MSE 손실, 타깃을 [0,1]로 정규화).
* 학습/평가: within-benchmark는 5-fold 교차검증(출력은 out-of-fold 예측), cross-benchmark는 3개 벤치로 학습 후 나머지 벤치로 평가.
* 모델 선택(RQ2): 기능적으로 정답을 생성하는 후보들(k≥2) 중에서 MRQS(정규화한 CSS/10와 MI/100의 조화평균)를 최대화하는 모델을 선택.
* 비교 전략: Random, Average-best, Prompt-embedding 기반(문장임베더 MiniLM-L6-v2 + 같은 MLP), PreMaQ(white-box), 결합(평균), Oracle(관측 상 최고).

## 주요 결과

- 데이터·대상: 4개 LLM, 4개 벤치마크(총 태스크 2,695; HumanEval+ 164, MBPP+ 378, BigCodeBench 1,098, LiveCodeBench 1,055).
- 활성화 소스 비교: Attention 출력이 AvgPassRatio/CSS/MI 예측에서 가장 높은 평균 Spearman 상관을 보임(표 IV).
- Within-benchmark 예측 성능: PreMaQ가 모든 16개 모델–벤치 조합에서 CSS와 MI에 대해 통계적으로 유의한 양의 상관 및 평균보다 낮은 MAE를 달성. 전체 평균 Spearman ρ는 CSS=0.57, MI=0.65 (AvgPassRatio 평균ρ≈0.32). (표 V)
- Cross-benchmark 일반화: 대부분 조합에서 양의 유의한 상관을 유지(16조합 중 15조합에서 CSS·MI에 대해 유의한 양의 상관), 다만 CSS의 경우 일부 벤치 간 성능 저하가 관찰됨. 교차평균(가중)은 CSS ρ 0.22(within 0.57), MI ρ 0.52(within 0.65), MAE는 CSS 1.56→2.82, MI 8.1→14.7으로 악화(표 VI).
- 모델 선택(RQ2, 대상 N=1,534 태스크): 각 전략의 평균 MRQS는 Random 0.426, Average-best 0.448(상대 이득 17.2%), Prompt-embedding 0.490(49.6%), PreMaQ 0.503(59.5%), PreMaQ+Prompt 0.504(60.7%), Oracle 0.555(100%) (그림 3). PreMaQ와 프롬프트 임베딩은 선택한 (태스크,모델) 쌍 중 약 39.9%에서 상이한 선택을 하며 상호보완적임(그림 4). 파일럿 예시(BigCodeBench/650)에서 PreMaQ가 보다 표준적이고 유지보수성 높은 구현을 선택함(본문 예시 비교). 예측/추론 비용: 내부 표현 추출(4모델 평균) 145.7 ms/태스크, 예측기 추론 0.252 ms, 예측기 학습(폴드) 약 14.0 s(표 VII).

## 한계

- 저자 언급: (1) 평가 지표로 CSS와 MI만 사용했으며 가독성·실행 효율성 등 다른 품질 측면을 포함하지 않음. (2) MRQS는 CSS와 MI를 결합하는 하나의 방식이며 다른 결합 방식에서는 결과가 달라질 수 있음. (3) 프롬프트 포맷, MLP 구성 등에 따라 성능이 변할 수 있음. (4) 외적 타당도 제한: 네 개의 로컬 오픈 모델 및 파이썬 벤치마크에 한정되며 더 큰 모델·다른 모델 계열·다른 언어로의 일반화는 미검증. (5) RQ2는 '기능적으로 정답을 생성하는 후보들이 알려져 있다'는 설정에 의존하며, 기능적 정합성 예측과의 종단간 통합은 평가하지 않음.
- 추가 관찰(본문에서 합리적으로 확인되는 한계): (6) Cross-benchmark에서 CSS 예측의 일반화가 약한 케이스들이 존재하여 데이터셋 특이 패턴에 민감할 수 있음(표 VI의 일부 음의 또는 낮은 ρ 셀). (7) 내부 표현 접근이 필요한 만큼 API 전용(black-box) 상용 모델에는 적용 불가하거나 불가능할 수 있음. (8) 예측기는 각 (모델,벤치,지표)마다 별도 학습이 필요하므로 모델·지표·도메인이 늘어나면 관리 오버헤드가 증가함.

## 개발자 관점

- 재현·구현: 내부 활성화(prefill activations)를 얻을 수 있는 오픈 웨이트 모델이 필요하다(최종 토큰 위치의 레이어별 Attention 출력 권장). 각 (모델,벤치,지표) 조합에 대해 입력 특징을 표준화(z-score)하고 MLP 회귀기를 MSE로 학습(타깃을 [0,1] 정규화). within-benchmark는 5-fold OOF 방식, cross-benchmark는 3-to-1 분리로 평가. 복제 코드는 공개 저장소에 제공됨(논문 본문에 링크).
- 배포·추론 비용: prefill 활성화 추출(프롬프트 포워드)은 주요 비용(논문 환경에서 평균 145.7 ms/태스크)이나 이는 전체 코드 생성·실행 비용보다 작음. 예측기 추론 비용은 매우 작음(≈0.252 ms). 이미 활성화를 사용하는 라우터(기능성 예측 등)가 있으면 추가 오버헤드는 미미함(활성화 재사용 가능).
- 운영 통합: 모델 선택 파이프라인에 기능적 정합성 예측과 MRQS 기반 유지보수성 예측을 결합하는 라우팅 정책을 권장(예: 먼저 정합성 가능성으로 후보 필터링 후 PreMaQ로 유지보수성 순위 결정 또는 다기준 가중 결합).
- 호환성/대체 전략: 내부 표현에 접근 불가한 환경에서는 프롬프트 임베딩 기반(black-box) 예측이 대안이며 본 연구에서는 상대적 이득 49.6%를 보였음. 내부 접근 가능 시에는 PreMaQ와 프롬프트 임베딩을 결합하면 추가 이득(60.7%)이 있음.
- 안전성·한계 인식: PreMaQ는 유지보수 관련 정적 지표(CSS, MI)를 개선하도록 도와주나 보안 취약점·성능 문제·가독성 전체를 보장하지 않음. 실전 도입 시 정적·동적 보안 검사 및 코드 리뷰 절차와 병행해야 함.

**근거 범위:** 이 분석은 제공된 논문 PDF 본문(페이지 1–10)에 근거하여 작성되었다. 모든 정량적 수치(상관계수, MAE, 태스크 수, 런타임 등)와 절차는 본문 표와 그림에서 직접 추출하였다. 본문에 명시되지 않은 하이퍼파라미터 세부사항(예: MLP의 은닉층 수/크기, 학습률 등)은 문서에 없어 기술하지 않았다. OCR/텍스트 추출 과정으로 인해 표 기호·특수문자 해석이 일부 달라 보일 수 있으나 주요 수치는 본문 표와 본문 문단을 대조해 확인하였다.
