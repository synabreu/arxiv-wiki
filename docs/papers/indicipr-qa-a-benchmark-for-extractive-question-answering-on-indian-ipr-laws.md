## 한 문장 요약

인도 7개 주요 IPR(지적재산권) 법령의 조문에서 정확한 추출형(answer-span) 답변을 제공하는 벤치마크 데이터셋 IndicIPR-QA를 GPT-4o로 자동 생성하고 9단계 자동검증·LLM 평가·200쌍 인간감사를 통해 정제한 뒤 BERT계열 인코더·오픈 LLM·BM25 성능을 비교·분석한 연구이다.

## 해결하려는 문제

기존 QA 벤치마크는 일반 도메인·계약·판결 등으로 편중되어 있으며, 인도의 7개 주요 IPR 법령 전체를 대상으로 조문 내에서 정확한 텍스트 스팬을 추출해 답변을 제공하는 추출형(extractive) QA 벤치마크가 부재하다. 법령은 긴 다중 절·중첩된 하위조문·전문 용어를 포함해 정확하고 근거 있는(법 조문에 직접 연결 가능한) 답변을 요구하므로 단순한 문서 검색이나 생성형 답변으로는 불충분하다. 본 연구는 이러한 한계를 해결하기 위해 인도 IPR 법령 전반에 대해 근거 가능한 추출형 QA 데이터셋과 이를 평가하는 프로토콜을 제시한다.

## 핵심 기여

- IndicIPR-QA: 인도의 7개 주요 IPR 법률(특허, 상표, 저작권, 디자인, 지리적표시, 반도체 레이아웃디자인, 식물품종보호)에 대해 1,116개 statutory contexts에서 생성·선별된 총 4,462개의 추출형 QA 쌍을 공개함.
- 데이터 생성·선별 파이프라인 제시: GPT-4o 기반 QA 생성(컨텍스트당 최대 5쌍)과 9단계 자동 필터(F1–F9), 컨텍스트 균형 선택, 섹션 단위 분할(train/val/test), LLM 기반 판정 및 200쌍 인간감사를 결합한 품질 검증 절차를 설계·적용함.
- 데이터셋 분석 및 벤치마크: 답변 길이·질문-문맥 어휘 중복·다중절 구조 등을 분석하고 BM25, 네 가지 BERT 계열 인코더(일반 BERT·LegalBERT-US·InCaseLawBERT·InLegalBERT) 및 세 개 오픈 LLM(예: Llama3.1, Mistral, Qwen2.5)을 일관된 슬라이딩 윈도우 추론 규약으로 비교함.
- 오류·일반화 분석: 인코더 모델의 주된 오류가 스팬 경계(boundary) 선택임을 규명하고, 섹션 단위 분할로 학습-테스트 컨텍스트 중복을 제거한 상태에서 테스트에 존재하는 미등장 토큰 비율(예: 테스트 답변 토큰 중 11.1% 미등장 등)을 보고함.

## 접근 방법

* 전체 파이프라인은 다섯 단계로 구성됨: (1) 원문 수집 및 전처리—India Code 포털에서 PDFs 수집(pdfplumber 사용), 목차·편집 표기 제거, 공백 정규화 후 문장 안전(sentence-safe) 기준으로 약 1,400자(δ=1400) 내외의 단락 수준 'statutory contexts' 1,173개로 청크화; (2) QA 생성—각 컨텍스트에 대해 GPT-4o에 구조적 JSON 출력을 요구하는 프롬프트로 최대 5개 추출형 QA 생성(답변은 컨텍스트에서 정확히 복사하도록 강제, yes/no·모호 질문 금지); (3) 9단계 자동 품질 필터(F1: 필드 비어있음 검사, F2: 답변이 컨텍스트 내 스팬인지, F3: 답변 길이 5–350 문자, F4: 답변이 컨텍스트의 85% 미만 차지, F5: 질문 품질(최소 5단어 등), F6: 질문 내 답변 포함 금지, F7: 문맥 잘림 제거, F8: 편집 표기 제거, F9: 숫자 전용 답변 제거)를 순차 적용하여 후보 축소(5,721 → 4,689 → 선택 후 4,462 쌍); (4) 컨텍스트 균형 선택과 섹션 레벨 분리—컨텍스트·섹션 단위로 그룹화 후 섹션 수준으로 stratified split(트레인/밸리데이션/테스트 = 3,710/408/344)하여 소스-컨텍스트 중복 제거; (5) 품질 검증—LLM-as-judge(단일 Gemma-3:12B 및 앙상블 Gemma/Llama3.1/Mistral)로 Q specificity, A sufficiency, A minimality, Legal relevance 평가 및 200쌍 인간 감사(두 명의 법학 졸업자).
* 모델 학습·추론: BertForQuestionAnswering 아키텍처로 토큰 단위 start/end 예측, 학습 하이퍼파라미터(AdamW, lr 3e-5, 50 warmup steps, weight decay 0.01, batch eff 32, max seq len 384, doc stride 128, 3 epochs, seed 42), 추론 시 오버래핑 슬라이딩 윈도우(stride 128)와 제약된 디코더로 윈도우 간 최적 유효 스팬 선택.
* 베이스라인으로 BM25(standard k1=1.5, b=0.75)와 오픈 LLM들(zero-shot/3-shot) 평가.

## 주요 결과

- 데이터셋: 4,462 QA 쌍, 1,116 retained statutory contexts(초기 컨텍스트 1,173), 섹션 기준 고유 section 수 681, 트레인/밸리데이션/테스트 = 3,710/408/344.
- 생성·선별 통계: GPT-4o로 생성된 원후보 5,721 쌍 → 9단계 자동 필터 적용 후 4,689 → 컨텍스트 균형 선택으로 최종 4,462 쌍(200쌍 인간감사 표본은 테스트에서 선정).
- 데이터 특성: 평균 답변 길이 35.6단어(중간값 33 단어), 평균 문맥 길이 171.3단어, 질문 평균 길이 11.9단어, 답변에 세미콜론 포함 비율 19.9%, 'subject to' 포함 5.9%.
- 인간 감사: 200쌍 표본에서 질문 명확성 joint accept. 99.0%, 답변 정답성 95.0%, 답변 최소성(최단 정답 스팬) joint accept. 75.5%; 인간 간 가중 κ는 답변 최소성에서 κQW=0.613 등.
- LLM-as-judge: 단일 Gemma 판정에서 222쌍(5.0%) 플래그, 앙상블에서는 26쌍(0.6%) 플래그. 단일 판정은 최소성에 대해 더 엄격하게 플래그함(Table III). 앙상블과 단일 판단이 다름을 보고함(전체 쌍의 8.0%만 모든 모델이 동일 점수).

## 한계

- [저자가 명시한 한계] 데이터셋은 영어로만 구성되고(answerable, single-context) 단일 컨텍스트에서 답할 수 있는 질문만 포함되며, 질문은 GPT-4o가 생성한 것임. 향후 독립적으로 작성된 질문, 인도 내 다른 언어, unanswerable 질문, 시나리오 기반·다중 섹션 질문을 포함하는 확장이 필요하다고 명시함.
- [저자가 명시한 한계] LLM-as-judge 평가는 진단용이며 인간 평가를 대체하지 않음(LLM 판정 간 불일치 존재). 인간 감사는 200쌍 표본에 대한 진단이며 전체 데이터 품질의 완전한 추정치가 아님.
- [본문에서 확인되는 제약] 질문 생성에 GPT-4o의 반복적 패턴이 존재하여(예: 'what does' 1,157회 등) 훈련/테스트에 동일한 질문 양식이 등장할 수 있어, 모델 성능은 '동일한 생성 프로세스로 만들어진 새로운 문맥'에 대한 일반화 성능을 측정할 뿐 사용자가 독립적으로 작성한 실제 법률 질문에 대한 직접적 성능 보장은 아님.
- [본문에서 확인되는 제약] 모델 오류의 주된 유형은 스팬 경계(boundary) 오류(예: InLegalBERT의 비-정확 예측 125개 중 100개(80.0%)가 경계 오류)로, 긴 다절(multi-clause) 답변과 긴 목록을 정확히 자르는 문제가 남아 있음.

## 개발자 관점

- 재현성: 데이터셋과 코드, GPT-4o 생성 프롬프트·스크립트가 공개되어 있어(논문 내 repo/허깅페이스 링크) 파이프라인 재현이 가능함(단, GPT-4o 호출 비용·접근성 고려 필요).
- 데이터 파이프라인 설계: 문장 안전 청크(약 1,400자)와 섹션 단위 분할은 학습-테스트 누수를 방지하기 위한 실무적 관행이며 법령 데이터셋 구축 시 권장됨.
- 품질 검증: 자동 규칙 필터(F1–F9)와 LLM-as-judge, 소규모이지만 도메인 인력(법학 졸업자)에 의한 인간 감사의 결합은 LLM 기반 생성 데이터의 품질 확보에 실용적임. 특히 답변 길이·커버리지 필터(F3,F4)가 후보 필터링에 큰 영향을 미침.
- 모델/추론: 긴 법령 문서를 다룰 때는 슬라이딩 윈도우(문맥 stride 128, max seq len 384)와 윈도우간 제약된 디코더로 최종 스팬을 결정하는 통일된 추론 프로토콜이 중요함. 또한 다수의 오류가 스팬 경계에 집중되므로 경계 민감 학습/정규화(예: boundary-aware loss, post-processing 정합성 검증)가 필요함.
- 성능 관점: 단순 BM25 기반 검색은 원천적으로 한계(기본 BM25 F1=20.21, oracle-window 51.30)이고 고정밀 추출형 성능을 위해서는 도메인 특화·미세조정된 인코더(InLegalBERT F1=85.02) 또는 적절한 유도/데코딩 전략이 필요함. 오픈 LLM(7–8B)도 준수한 성능을 보였지만(few-shot/zero-shot F1~68–77) 미세조정된 인코더 대비 여전히 차이가 있음—생산 환경에서는 비용·지연·정확성 트레이드오프를 고려해야 함.

**근거 범위:** 이 분석은 요청자가 제공한 논문 PDF 본문 텍스트에 근거해 작성되었으며(초록은 보조로 사용), 표·표 숫자·문장 등 본문에 명시된 수치와 절차를 직접 인용·요약했다. 데이터셋·코드 링크, 표의 수치(예: F1/EM/Char-F1, 샘플 크기, 필터 제거 수 등)는 PDF 본문에서 확인 가능한 값만 사용했다. 외부 저장소(허깅페이스·깃허브)나 원본 PDF 외 추가 자료는 직접 열람하지 않았으므로 그 안의 세부 내용은 본 분석에 포함되지 않았다.
