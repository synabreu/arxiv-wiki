## 한 문장 요약

기관의 데이터사전과 안전분석 규약에 기반한 완전 로컬의 에이전트형 워크플로인 CrashDB-QA를 제안하여 자연어 질문을 읽기 전용 SQL로 변환·검증·실행·설명하고, 선택적 검사 모듈(CrashDB-QA+)로 질문·쿼리·실행 결과의 정렬을 검사해 반복 수정을 지원한다.

## 해결하려는 문제

기존 대시보드는 미리 정의된 분석만 지원하고 추가 분석 요청은 데이터베이스 쿼리, 코드화된 필드, 기관 규약을 이해하는 전문가에 의존한다. 본 연구는 실무자가 자연어로 제시한 분석 질문을 신뢰할 수 있는 결과로 유연하게 변환·검증할 수 있는 완전 로컬·스키마 기반 워크플로를 만들 수 있는지를 다룬다.

## 핵심 기여

- CrashDB-QA라는 완전 로컬, 스키마-그라운디드(agentic) 워크플로를 제안: 질문 해석, 읽기 전용 SQL 생성·검증, 쿼리 실행, 결과 설명을 담당하는 전문화된 구성요소들을 포함.
- 기관의 데이터 사전(data dictionary)과 안전분석 규약을 담은 공유 지식기반을 통해 쿼리 생성 시 도메인 기반 근거를 제공하고, 중간 출력들을 기록해 검사 및 감사 가능하도록 설계.
- 선택적 확장인 CrashDB-QA+를 도입하여 질문·쿼리·실행 결과 간 정렬(alignment)을 점검하고, 근거를 제시하며 반복적 수정을 지원하는 Judge/Refiner 스타일의 검증 절차를 제시.
- 4.4백만 건(위스콘신 교통사고 스냅샷)의 실제 데이터에 대해 10개 분석 범주, 300개 질문으로 구성된 벤치마크를 만들고, 9개의 로컬 오픈-웨이트 모델에서 시스템을 평가하여 도메인 그라운딩과 모델 특화(코드 특화 7B)의 성능·응답시간 균형 효과를 보고.
- 중간 출력 기록·검증 절차·로컬 배포를 강조함으로써 실무자 접근성 확대와 감사 가능성(auditability)을 향상시키는 설계 원칙을 제시.

## 접근 방법

* 시스템은 질문을 해석하는 모듈, 읽기 전용 SQL을 생성·검증하는 모듈, 쿼리를 실행하는 실행기, 실행 결과를 설명하는 모듈로 구성된 에이전트형 워크플로이다.
* 쿼리 구성과 용어 선택은 기관의 데이터 사전 및 안전분석 규약을 담은 공유 지식기반으로부터 근거를 가져와 스키마-그라운딩을 수행한다.
* 중간 출력(예: 생성된 SQL, 검증 로그, 실행 결과 등)을 기록해 검사·감사에 활용한다.
* 선택적 확장인 CrashDB-QA+는 질문, 생성된 쿼리, 쿼리 실행 결과 간의 정렬을 검사하는 Judge와, 필요시 실행 증거를 받아 쿼리를 반복적으로 수리하는 Refiner를 포함한다.
* 평가에서는 완전 로컬 환경에서 9개의 오픈-웨이트 모델을 사용해 응답성과 정확도(정확도 관련 정량치는 본문에 수치로 제시되지 않음)를 비교했으며, 코드 특화 7B 모델이 정확도-대기시간 균형에서 최적이라고 보고되었다.
* 모든 쿼리는 읽기 전용으로 설계되어 데이터 무결성과 안전을 고려한다.

## 주요 결과

- 평가 데이터: 위스콘신 주의 교통사고 스냅샷 4.4백만 레코드(고정 스냅샷).
- 벤치마크: 10개 분석 범주에 걸쳐 300개 자연어 질문으로 구성된 새로운 벤치마크를 사용해 평가.
- 모델 비교: 9개의 로컬 오픈-웨이트 모델을 비교했으며, 도메인 그라운딩(데이터 사전 기반)이 쿼리 정확도를 실질적으로 향상시켰다고 보고.
- 모델 성능-지연 균형: 코드 특화된 7B 모델이 테스트된 모델들 중 정확도와 응답시간의 균형 측면에서 최적이라고 기술됨.
- 질적 패턴: 조합적(compositional) 분석—특히 그룹 간 또는 기간 간 비교—은 단순 검색·조회보다 더 어려웠고 정확도가 낮은 경향을 보였음. 검증 절차(즉, CrashDB-QA+)는 Judge가 권위있는 필드 정의를 사용할 때와 Refiner가 실행 증거를 받을 때 성능을 개선했으며, 단순한 추가 검사만으로는 일관된 이득을 주지 못했다고 보고됨.

## 한계

- 저자가 언급한 한계: 조합적 분석(특히 그룹 간 혹은 기간 간 비교)은 여전히 더 어렵고 신뢰성 있는 정답을 얻기 힘들다; 검증 절차는 Judge가 권위 있는 필드 정의를 사용하고 Refiner가 실행 증거를 받을 때에 유의미한 개선을 주며, 단순히 추가 검사만 하는 것은 일관된 이득을 제공하지 않는다.
- 본문에서 합리적으로 확인되는 한계: 평가가 단일(위스콘신) 데이터 스냅샷(4.4M 레코드)과 저자 구축 벤치마크(300문항)에 한정되어 있어 다른 주나 다른 기관의 스키마·코딩 관행으로 일반화 가능성은 본문에서 직접 증명되지 않음. 또한 제공된 텍스트(초록 수준)에는 정확도 수치, 통계적 유의성, 하드웨어·추론 대기시간의 구체적 수치 등 세부 실험값과 구현 파라미터가 제시되지 않아 재현과 세부 성능 비교에 제약이 있음.

## 개발자 관점

- 재현을 위해서는 원본 데이터(또는 동등한 규모의 사고 레코드), 완전한 데이터 사전(data dictionary) 및 기관별 안전분석 규약을 확보해야 한다. 지식기반을 데이터 사전에 맞춰 구축하는 것이 핵심이다.
- 시스템 설계 시 모든 쿼리를 읽기 전용으로 제한하고 쿼리 생성·검증 로그와 실행 결과 등 중간 산출물을 기록해 감사·검토 기능을 갖추라.
- 현장 적용에서는 스키마-그라운딩(권위 있는 필드 정의 사용)이 쿼리 정확도에 중요한 영향을 미치므로, 도메인 전문가가 검토한 필드 매핑·정의 자료를 통합하라.
- 검증 루프(CrashDB-QA+)를 도입할 경우 Judge가 권위있는 정의를 사용하게 하고 Refiner에게는 쿼리 실행 증거(예: 결과 샘플·에러 메시지)를 제공해야 실질적 이득이 난다. 단순히 추가 검사만 넣는 것은 비용 대비 효과가 불확실하다.
- 모델 선택과 배포 관점에서는 코드 특화 7B급 모델이 정확도-지연 시간 균형 면에서 실용적일 가능성이 크다. 다만 '완전 로컬' 배포는 모델 추론을 위한 하드웨어(메모리·GPU/가속기)와 데이터 저장 비용을 고려해야 한다—추정 비용 수치는 본문에 없음이므로 사전 용량 계획이 필요하다.

**근거 범위:** 이 분석은 제출된 '논문 PDF 본문'으로 제공된 텍스트(초록 수준 내용)에 전적으로 기반함. 원문 PDF 추출 실패(HTTPError)로 인해 본문 전반의 세부 구현, 정량적 수치(정확도·대기시간 등), 하드웨어·하이퍼파라미터, 실험 세부설정 등은 확인 불가하며 본 분석에는 그러한 미확인 정보가 포함되어 있지 않음.
