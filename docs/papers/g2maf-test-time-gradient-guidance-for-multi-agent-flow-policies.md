## 한 문장 요약

오프라인으로 학습된 동결된 다중 에이전트 생성 정책이 제안한 공동 행동을 테스트 시점에 중앙화된 행동-가치(critic) 기울기로 한 걸음 조정하여 협력 성능을 회복하는 G2MAF 검정·투영 기반 정제 프레임워크를 제안한다.

## 해결하려는 문제

오프라인 MARL에서 학습된 정책은 배포 시 동결되어 단일 샘플 공동 행동을 바로 실행한다. 이 일회적 실행은 행동 데이터로 여전히 지지되는 더 나은 인근 대안이 존재하더라도 서브옵티멀한 제안에 고착될 수 있다(로컬 조정만으로 팀 리턴을 크게 올릴 여지가 존재함). 연구 질문은 "동결된 공동 정책과 동결된 중앙화 행동-가치 함수를 유지한 채, 테스트 시점에 하나의 로컬, 중앙화된 critic 기울기 업데이트만으로 공동 행동을 효율적으로 개선할 수 있는가" 이다.

## 핵심 기여

- 협력적 동결 생성 정책의 'coordination gap'을 중앙화 critic이 제안한 동작과 더 높은 점수를 가지는 인근 실행가능 행동 간의 국소적 점수 차이로 정식화함.
- G2MAF: 하나의 전역 정규화된 중앙화 critic 기울기를 취해 공동 행동 전체를 한 번 업데이트하고 행동집합으로 투영(ΠA)하여 실행가능성을 보장하는 테스트-타임 정제 연산자를 제안함; 연속·이산·궤적(흐름) 주입 변형을 제시함.
- 국소 매끄러움과 충분히 작은 스텝 크기 하에서 적용한 단일 업데이트가 critic 예측값을 증가시킨다는 형식적 국소 상승 보장(부등식으로 제시)을 제공함.
- 24개 MPE 및 SMAC 설정에서 테스트하여 canonical(사후-action-space) 변형이 20/24 설정에서 동결 백본을 개선함을 보이고, MPE 평균 상대 이득 9.2%·SMAC 평균 상대 이득 8.9%를 보고함(모델측 지연은 약 1.06×로 증가).
- 주입 위치(궤적 공간 All/Final vs. 사후 Post)와 이산 마스킹 로짓 처리, 일회 역전파(critic backward)만 사용하는 배포 비용 측정(평균 역전파 3.85 ms, 전체 모델측 지연 157.86→167.11 ms)을 포함한 광범위한 분석·대조 실험을 수행함.

## 접근 방법

* 구성요소: (1) 동결된 공동 생성 정책(코디네이티드 few-step flow; CGB), (2) 동결된 중앙화 행동-가치 함수 Qϕ(o,a) (행동 연속/이산 모두에 대해 중앙화 입력).
* 추론 절차(한 의사결정마다): (A) 정책이 조건(g,target return)과 joint observation o로부터 실행 가능한 공동 행동 aθ를 제안한다.
* (B) 중앙화 critic을 aθ에 대해 미분하여 전체 joint-action 벡터의 기울기 d = ∇aQϕ(o,aθ)를 얻는다.
* (C) 기울기를 전체 결합 노름으로 정규화하고 스텝 크기 η를 곱한 뒤 행동 공간 제약(박스)으로 유클리드 투영하여 ˜a = ΠA(aθ + η d/(\|\|d\|\|2+ε)) 를 실행한다(연속).
* 이산(SMAC)에서는 각 에이전트의 logits ℓi에 마스크 적용 후 softmax 확률 p를 만들고 ∇ℓQϕ(o,p)를 구해 정규화된 로그it 업데이트를 수행한 뒤 불법 행동을 다시 마스킹하고 argmax로 행동을 선택한다.
* 궤적-주입 변형은 few-step flow의 중간 normalized trajectory 변수들(zk 등)에 critic 신호를 체인룰로 전파하여 역오일러 단계들에서 값신호를 주입(All/Final)하고, Post는 디코딩 이후 행동공간에서 업데이트를 수행한다.
* 구현 세부: 전역 정규화는 팀 단위의 단일 수정 예산을 제공하며, ε(=1e-6)로 안정화; 투영은 좌표별 클립; critic 학습은 FQE(행동 지속 bootstrapped TD)로 ϕ를 20k 스텝 학습(4-layer MLP, 512 유닛, LayerNorm, SiLU, γ=0.99, τ=0.005).

## 주요 결과

- 평가: MPE(12 continuous 설정: Spread, Tag, World 각 데이터 품질별) 및 SMAC(12 discrete 설정: 3m, 2s3z, 5m_vs_6m, 8m 각 품질별) 합계 24 설정에서 실험.
- 주요 성능: canonical(Post) G2MAF는 24개 설정 중 20개에서 동결(frozen) 백본 대비 개선을 보였고, 보고된 운영점(테이블1)에서 MPE 평균 상대 이득 9.2%, SMAC 평균 상대 이득 8.9%를 달성함(논문 본문과 초록 수치).
- 검증 지표: paired rollouts(실제 시뮬레이터 리턴), critic 진단(로컬 순위 정확도), 주입-위치 비교, 매치된 반경 통제, 배포 비용 측정을 포함. Critic의 지역적 순위 판별력은 24개 설정 중 23/24에서 시뮬레이터 리턴을 무작위보다 유의하게 더 잘 랭킹함(본문).
- 주입 위치: few-step flow에서 'All'(모든 역오일러 단계에 주입)이 12개 MPE 설정 중 8개에서 최대로 성능 향상, 'Final'은 1개, 'Post'(사후 디코딩 action-space canonical)는 3개에서 최대로 나타났음. Post는 구현과 배포 측면에서 선호되어 대부분의 보고된 결과에 사용됨.
- 스텝 전이(LOTO): 도메인 내 비오라클(step 선택) 전이는 MPE에서 11/12, SMAC에서 7/12로 총 18/24에서 양의 이득을 보였음(본문 Table 5(a)). 이로써 스텝 선택은 도메인·행동 표현에 민감함을 시사함(특히 SMAC에서 더 약한 전이).

## 한계

- 저자가 명시한 한계: G2MAF는 중앙집중식 접근(중앙화된 관측 및 행동 접근)과 인근 행동들을 신뢰성 있게 랭킹할 수 있는 critic 가용성을 가정한다. 동결된 제안에 로컬 헤드룸이 거의 없으면 이득이 제한적이며, critic의 잘못된 랭킹은 실제 리턴 감소를 초래할 수 있다.
- 저자가 명시한 범위 한계: 실험은 두 가지 벤치마크 계열(MPE, SMAC)과 선택된 운영점에 국한되며, 더 큰 팀 규모, 강한 분포 이동, 분산(비중앙화) 실행에 대한 평가는 향후 작업으로 남김.
- 실험·분석에서 드러나는 제약: 유용한 스텝 크기 η는 작업과 행동 표현(연속 행동 vs. 마스킹된 로그it)에 따라 크게 달라지므로 운영점 선택이 중요하고, SMAC에서는 LOTO 전이가 약해 도메인별 튜닝이 필요함.
- 구현적 제약: 중앙화 critic과 중앙화 코디네이터가 필요하므로 일부 실세계 분산 제어 시나리오에 바로 적용하기 어려움(비동기·분산 통신 비용·보안 문제 미고려).

## 개발자 관점

- 재현·구현 핵심: G2MAF는 배포 시 actor나 critic 파라미터 업데이트 없이 동결 모델에 '행동 편집'만 수행한다. 필요한 것: (1) 동결된 공동 정책(예: CGB flow), (2) 동결된 중앙화 critic Qϕ. 각 의사결정마다 한 번의 critic 역전파만 수행하면 됨(모델측 오버헤드 작음).
- critic 학습·구성: 논문 본문(Appendix B)에 따르면 critic은 concatenated joint (obs,action) 입력의 4-layer MLP(512 유닛, LayerNorm, SiLU)로 학습되며 FQE 형태로 20k TD 스텝, γ=0.99, 타깃 소프트 업데이트 τ=0.005로 학습함—재현 시 동일 구성·데이터로 critic을 학습해야 동작 보장 가능성이 높음.
- 스텝 크기·주파수: 연속 행동은 η 정규화된 그라디언트 기준으로 연속 그리드(논문은 실험에 η∈{0.01,0.03,0.05,0.1,0.2,0.3,0.5} 등을 사용), 이산은 로그it 스텝 {2,10,50} 등으로 탐색. 운영점 선택은 도메인별로 민감(특히 이산 SMAC). LOTO 전이 결과를 참고해 도메인-레벨 스윕을 권장.
- 주입 인터페이스: 간단히 적용하려면 Post(디코딩 후 행동공간 업데이트)를 사용하라(구현이 간단하고 별도 정규화된 좌표 critic 불필요). few-step flow의 내부 주입(All/Final)은 decoder Jacobian을 통해 체인룰을 적용해야 하므로 별도 정규화된 critic(Qnorm) 또는 추가 구현 복잡성이 필요하다.
- 실행·배포 비용: 논문 측정 결과 critic backward 평균 3.85 ms, 전체 모델측 지연은 평균 157.86→167.11 ms(약 1.06×, 즉 약 6% 증가). 따라서 실시간성 요구가 극히 엄격하지 않은 시스템에서 적용 가능(단 중앙화 coordinator의 통신 비용은 환경에 따라 추가될 수 있음). 성능·지연 트레이드오프를 고려해 η를 선택하라(작을수록 안전한 국소 상승 보장).    

  안전성·운영 고려: critic의 잘못된 랭킹(과추정/오프-데이터 영역)은 실세계 리스크를 줄 수 있으므로 보수적 검증(held-out rollouts, critic pairwise accuracy 검사)을 도입하고, 분산 실행이 필요한 경우 중앙화 요구사항을 충족하거나 대체 아키텍처(예: 중앙화 코디네이터 + 라이트한 통신) 설계를 고려하라.

  추가 실무 팁: 투영(ΠA)과 전역 정규화는 구현상 간단(노름 계산→스케일링→클립)하므로 기존 정책 인퍼런스 파이프라인에 비교적 쉽게 끼워넣을 수 있음. 이산 도메인에서는 마스킹과 softmax relaxation을 통해 미분을 얻고 업데이트 후 다시 마스크·argmax로 결정하는 절차를 동일하게 구현해야 함.
