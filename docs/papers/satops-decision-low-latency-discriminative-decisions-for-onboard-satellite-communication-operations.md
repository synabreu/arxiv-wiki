## 한 문장 요약

후보 응답을 단일 인코더 전방전파로 직접 점수화하는 도메인 적응형 Laya 판별자(scorer)를 사용해 위성 통신 운영에서 저지연 의사결정을 수행하고, 이를 위한 Jev-스타일 전용 벤치마크를 제시한다.

## 해결하려는 문제

위성 통신 운영은 제한된 접촉 시간·자원과 시간 민감한 증거(freshness)를 다루므로 의사결정 지연이 실무적 비용을 초래한다. 기존의 생성형 LLM은 응답 디코딩(autoregressive generation) 때문에 단건 요청의 지연이 크고, 이는 증거 유효성·스위칭 허용 조건 등 운영 제약을 만족시키기 어렵게 만든다. 연구 질문은 '후보 답안 집합을 직접 점수화하는 Jev-스타일 판별 모델이 도메인 적응을 통해 정확도를 개선하면서 생성 기반 접근보다 낮은 요청 지연을 유지할 수 있는가' 이다.

## 핵심 기여

- Jev-스타일 일반 목적 판별(decision) 모델을 위성 통신 운영에 적용한 최초 사례(SatOps-Decision) 및 도메인 적응형 Laya 로컬 스코어러 제안.
- Jev-스타일 위성 운영 전용 벤치마크 제안: 명시적 운영 계약(operational contract), 통제된 상태 변경, 독립 검증 라벨을 포함한 재현 가능하고 감사 가능한 구성.
- 후보 직접 점수화를 통해 단일 전방전파로 답안을 선택하는 아키텍처와, 이를 위한 학습/추론·운영 검사(결정 후의 명시적 불허용(거부) 검사) 파이프라인 설계.
- 동일한 1,024개 보류 질문(held-out)에서 로컬 적응 모델의 지연·정확도 실험 비교를 수행하고, 생성형 Qwen, OneJev 로컬, 원격 Jev API(참고치)와 정량적 비교를 제시.

## 접근 방법

* 아키텍처: ModernBERT-large 기반의 Laya bidirectional encoder(421M 파라미터)와 native decision head를 공유 스코어러로 사용한다.
* 입력으로 정책(r), 타임스탬프가 있는 증거(x), 질문(q), 후보 의미 집합(A)을 받아 각 후보에 대한 로짓 z_theta(a)를 계산하고 masked softmax(Choice scoring)로 p_theta(a\|r,x,q,A)를 얻는다(단일 전방전파, 비자동회귀).
* 손실과 학습: native option cross-entropy로 학습(L(θ)=−∑ log pθ(y_i\|...)).
* 학습 세부: 고정된 1,536 훈련 질문, 개발 256, 테스트 1,024; 3개 시드(7/17/29)로 각각 훈련; 4 에폭, 총 384 AdamW 업데이트(마이크로배치4, 누적4 → 유효배치16), encoder/head 학습률 2.5e-5/1e-4, weight decay 0.01, grad-norm clip1, 5% warmup 후 cosine decay, FP32와 gradient checkpointing 사용.
* 토큰 예산: 전체 1,024, 질문/옵션 256; native augmentation은 옵션 순서 치환과 타깃 매핑 재매핑을 수행.
* 추론: 온전한 후보 점수는 온도 1로 반환되어 argmax로 결정.
* 운영 경계 및 체크: 결정 후 별도의 결정성 검사기가 (저자 정의의) 증거 유효성 조건(식(3))과 스위칭 허용 조건(식(4))을 평가하여 금지되는 긍정(허가/스위치 등)을 거부(veto)한다.
* 벤치마크 생성: (1) 시드 기반 정책·정상 상태 샘플링, (2) 제어된 변형(백업 준비성, 에너지, 접촉 종료 등), (3) 독립 구현 간 라벨 합치기, (4) 질문 문장·답안 슬롯 렌더링 다양화 — 모든 모델은 동일한 정책·상태·후보 설명을 수신하되 라벨은 제외.

## 주요 결과

- 데이터셋·분할: 훈련 1,536 질문(roots 1,536), 개발 256(roots 64), 표준 테스트 1,024 질문(roots 256) 등으로 고정 분할; 각 테스트 입력은 동일 순서로 모든 모델에 제공.
- 지연(latency, 동일 데스크탑 환경·측정법): 측정 환경은 Apple M6, macOS 27.0, PyTorch MPS, FP32, 4 호스트 스레드; 각 모델에 대해 384 timed 요청(128 질문 × 3 패스) 측정. 중앙값(median) 완전-요청 지연: SatOps-Decision 90.3 ms(P95 104.7 ms), Frozen Laya 91.2 ms(P95 104.5 ms), Qwen3.5-0.8B 493.9 ms(P95 507.8 ms), OneJev1.6-0.8B 388.4 ms(P95 403.0 ms). 동일 조건에서 SatOps-Decision은 Qwen 대비 5.47×, OneJev 대비 4.30×의 중앙값 속도 우위.
- 정확도(1,024 표준 테스트, raw scorer 결과): SatOps-Decision 평균 85.3 ± 0.8% (세 시드별 정답 수: 865, 882, 872), Frozen Laya 42.5%, Qwen3.5-0.8B 40.7%, OneJev1.6-0.8B 58.6%. 원격 Jev API(참고치): Jev 1.14 = 87.4%, Jev 1.13 = 81.9%.
- 태스크별 적응 성능(각 256 질문): assessment 74.5% vs frozen 37.1%, action 89.1% vs frozen 25.8%, permission 78.9% vs frozen 53.9%, recovery 98.6% vs frozen 53.1%.
- 적응 이득 및 대조: 도메인 적응으로 frozen Laya 대비 평균 42.77 퍼센트포인트 개선(페어드 root-bootstrap 95% 구간 [40.14,45.15]). 체크된(운영 검사 후) 시스템은 단순 raw scorer 대비 평균 표준 정확도를 93.3%로 증가시킴(논문 본문 언급). 주요 오차 유형은 허가(permission)에서의 '거짓 허가(false authorization)'로, 적응된 각 시드는 금지되어야 할 128개 권한질문 중 평균 54개(42.2%)를 잘못 허가함; 반면 적격 스위치 차단은 없음.

## 한계

- 저자가 직접 언급한 한계: 입력 표현(operator-note) 전이와 복구(recovery) 결정 개선이 필요하며, 향후 실 텔레메트리, 특정 임무 제약 및 온보드 하드웨어에서의 검증이 필요하다고 명시함.
- 실험 범위·구성에서 합리적으로 확인되는 한계: 벤치마크는 모든 상태·정책·수치·문장 템플릿을 저자가 작성한 합성 데이터이며(에너지는 '합성 퍼센트포인트'), 실제 미션 텔레메트리·잡음·비정형 입력과의 일반화는 불확실함; 성능·지연 측정은 macOS/Apple M6 FP32/MPS 데스크탑 구현에 한정되어 온보드(임베디드) 하드웨어나 다른 정밀도(예: FP16/INT8)에서 달라질 수 있음; 훈련 데이터가 상대적으로 작음(1,536 질문)과 세드/체크포인트 선택 절차로 인한 불안정성 가능성; 원본 Jev 가중치는 로컬에 없어 Jev 결과는 클라우드 API 참조치로만 제공되어 내부 구조 비교가 제한됨; operator-note(자유문장 렌더링)에서의 전이는 낮아(적응 Laya 47.4% vs OneJev 56.9%) 표현 양식 변화에 취약함; 권한(permission)에서 '거짓 허가' 비율이 높아 실행 전의 결함 방지를 위해 결정성 검사(veto)가 필수임.

## 개발자 관점

- 재현성: 논문은 사용한 체크포인트(421M Laya), 학습 데이터 개수(1,536/256/1,024), 세부 하이퍼파라미터(학습률, 배치·누적·업데이트 수, 4 에폭, FP32, gradient checkpointing), 토큰 예산(전체 1,024, 질문/옵션 256)과 세드(7/17/29)를 명시하므로 동일 환경에서 재현 가능. 체크포인트 선택은 개발(dev) 세트 성능에 기반해 이루어졌음을 반드시 재현 파이프라인에 반영할 것.
- 저지연 배포: 단일 전방전파로 후보를 점수화하면 생성 기반 디코딩 비용을 제거해 단건 지연을 크게 줄일 수 있음(데스크탑 기준 중앙값 ~90 ms). 온보드 적용 시에는 대상 하드웨어(정밀도, 메모리, 가속기)에서의 완전-요청(latency end-to-end)을 재측정하고 예산(논문은 의사결정 간격 0.5 s 기준 사용)을 맞출 것.
- 운영 안전성: 학습된 scorer는 '거짓 허가' 같은 방향성 오류를 보이므로 실행 전 반드시 결정성 검사(operational contract 체크)를 두어 금지되는 긍정을 veto해야 함. 이러한 체크는 설계상 필수 안전 계층이다.
- 훈련·데이터 관점: native augmentation(옵션 순서 치환 등)을 적용해 후보 표면적 단서를 억제하고 의미 기반 매핑을 학습시키는 것이 중요하다. 또한 encoder와 head를 함께 적응(fine-tune)해야 높은 이득을 얻음(완전 적응 ≫ head-only).
- 검증·기능 테스트: operator-note(자유문장) 전이 성능과 복구 검증 시퀀스는 약점으로, 실제 텔레메트리·노이즈·문장 다양성에 대해 교차점검용 스트레스 테스트와 회귀 테스트를 준비할 것. 또한 계약(식(3),(4)) 구현은 독립적으로 검증 가능한 참조 구현으로 유지해 감사 가능하도록 할 것.
