## 한 문장 요약

복합적 요구(편집 목표, 보존, 참조 제약)를 항목별 체크리스트와 시각적 근거로 진단하는 WeGenEditBench와, 그 진단을 대상화된 데이터 처방·검색 기반 합성·감독학습으로 연결하는 다중 에이전트 개선 허브 WeGenEvoStudio를 제안해 모델 평가에서부터 반복적 경험 획득까지 잇는다.

## 해결하려는 문제

실제 이미지 편집 요청은 여러 시각적 변환을 동시에 요구하고 보존·참조 제약을 동반하므로, 단일 집계 점수(또는 두드러진 시각적 변화 기준)는 국지적 실패나 제약 위반을 가릴 수 있다. 따라서 실패를 원자적 요구 단위로 노출하고, 그 근거를 학습용 우선순위(데이터 처방)로 변환해 재학습·재평가하는 체계가 필요하다.

## 핵심 기여

- WeGenEditBench: 단일-이미지, 텍스트집중, 다중참조의 2,740개 인스턴스·148개 작업 유형을 포함하고, 사전생성된 샘플별 체크리스트로 원자적 요구를 기록하는 세부적 평가 프로토콜을 제시함.
- 체크리스트 기반 증거: 고정 VLM 판정자가 항목별 시각적 근거와 0–5 점수(δi,j)를 먼저 기록한 뒤 차원별(EG, PR, VQ, DS) 점수를 집계하여 집계점수의 은폐 문제를 완화함.
- WeGenEvoStudio: 진단(Diagnosis)→검색기반 합성(Construction)→감독적 적응(supervised adaptation)→재평가의 다중 에이전트 파이프라인을 제안하여 평가 결과를 목표지향적 데이터 생성과 모델 갱신으로 연결함.
- 대규모 비교 및 진화 실험: 15개 구성(폐쇄·오픈 모델)을 WeGenEditBench로 진단하고, Qwen·FLUX.2에 대해 진단-처방-합성-LoRA 적응-재평가 실험을 수행해 목표화된 성능 향상과 교차-차원 트레이드오프를 보고함.
- 진단-처방 연결성·투명성: 체크리스트 항목·시각적 근거·진단 통계를 통해 어떤 항목이 반복적으로 실패하는지, 어떤 데이터가 필요한지 추적 가능하게 설계함.

## 접근 방법

* WeGenEditBench: 3개 설정(단일-이미지, 텍스트집중, 다중참조), 총 2,740 인스턴스·148 작업유형.
* 각 인스턴스에 대해 편집목표(EG), 보존(PR), 시각품질(VQ), 도메인특화(DS) 항목으로 분해한 사전생성 체크리스트를 고정·공유함.
* 고정 VLM(논문 본문에서는 gemini-3.1-pro-preview 사용) 판정자가 항목별 시각적 근거를 기록하고 항목점수 δi,j∈[0,5]를 매긴 뒤, 샘플별 중요도 규칙에 따라 차원 점수를 산출한다.
* 단일-이미지·텍스트집중·다중참조별 집계식(논문 식(1),(2))으로 Overall을 산출한다.
* WeGenEvoStudio: gemini-3-flash-preview 기반 오케스트레이터와 68개 도구 레지스트리를 갖춘 다중 에이전트 허브.
* Diagnosis Agent는 카테고리 평균 점수¯Sc(θt)와 앵커 모델 점수를 비교해 상대결손 Δrel_c를 계산하고(선정 공식 Cseed 참조), 사례 간 VLM 리뷰로 누락된 작업·영향 객체·비의도적 변경을 추출해 처방 Tt(작업 라벨 ψ(c), 소스 조건 Sc, 편집·보존 요구, 할당량 Nc) 생성.
* Construction Agent는 처방에 따라 웹/라이브러리 검색으로 적절한 소스 이미지·개념을 회수하고, 편집 지시문을 합성·검증(실현가능성 체크·VLM 재작성).
* 합성이 승인되면 고성능 생성 백엔드로 타깃 이미지를 합성하고 시각품질·정렬 필터로 고신뢰 학습셋 Dt 생성.
* 모델 업데이트는 논문 실험에서 LoRA(rank=16) 어댑터로 수행(Train(θt,Dt;λt))하고 재평가해 루프를 닫음.
* 진단→구성→학습→재평가의 흐름은 RSI 지향 개선을 지원.

## 주요 결과

- 주요 리더: 단일-이미지 편집에서 GPT-Image-2 Overall 4.076(표 1), 텍스트집중 편집에서 Seedream-5.0-Pro Overall 4.291(표 2).
- 원자적 실패 노출: GPT-Image-2의 single-image 출력 중 Overall≥4인 644개 중 315개(48.9%, 95% CI [45.1%,52.8%])에 항목점수≤2인 심각 실패 항목 존재. Overall≥4.5인 경우에도 심각 실패 비율 31.3%로 집계됨(본문).
- 모델 진화(보고된 사례): WeGenEvoStudio로 적응시킨 FLUX.2 [dev]의 보고된 Top-5 single-image 대상에 대해 Overall이 1.083→3.517로 향상(∆≈+2.434, 표 4). Qwen-Image-Edit-2511은 WeGenEditBench-SingleImageEdit 타겟에서 Overall +0.373(약 13.2% 상대 향상)을 기록(본문·표 4).
- 피드백 형식 범용성: GEdit·ImgEdit(거친 카테고리 점수), WeGenBench(기본 근거), WeGenEditBench(세부 체크리스트) 등 다양한 피드백 그레인 수준에서 데이터 처방·적응을 적용해 목표화된 개선을 확인함(표 4 및 본문).
- 교차-차원/백본별 트레이드오프: 강한 개선이 항상 모든 차원에서 일치하지 않음. 예: Qwen 적응은 EG·VQ 향상에 집중되었으나 PR 안정·DS 소폭 하락을 보였고(본문), FLUX.2는 상대적으로 모든 차원에서 큰 개선을 보였음(표 4).

- 본문에서 확인되는 제약·한계:
- 평가자·판정 의존성: 체크리스트 기반 평가가 고정 VLM(gemini-3.1-pro-preview) 판정자와 규칙화된 중요도·집계 식에 의존하므로, 판정자 모델·규칙 설계에 따라 진단 결과가 변할 수 있음(본문에 해당 VLM 사용 명시).
- 데이터·적응 예산 제약: 적응 실험은 LoRA rank-16, 25,000 합성 예제(Top-K=5 카테고리, 카테고리당 5,000), 32 Cambricon MLU590 디바이스, per-device batch size=1 등 특정 예산·하드웨어 조건에서 수행되어 규모·비용 제한에 따라 결과가 달라질 가능성이 있음(본문 실험 설정에 명시). 재현 시 동일한 생성 백엔드·오케스트레이터·검색 라이브러리 접근이 필요함.」「진단 대상·모델 범위 제한: 실험은 15개 구성에 한정되며 다중입력 편집을 지원하는 모델은 6개에 불과하여(본문), 다중참조 일반성 검증이 제한적임.」「검색·합성의 개념 편향성: 본문 실험에서 검색 기반 확장(retrieval)이 일부 범주(저빈도 개념)에는 이득을 주나 이미 잘 대표된 범주에는 성능 저하를 일으킬 수 있음을 관찰했음(본문), 따라서 처방에 따른 선택적 검색 전략 필요.

## 개발자 관점

- 평가 설계: 복합 요구를 평가하려면 사전 생성된 샘플별 체크리스트와 항목별 시각 근거를 기록하는 절차가 중요함 — 집계점수만으로는 국소 실패를 가림. 평가 파이프라인에 고정된 VLM 판정자와 감사(본문: 10% 사례, 3명 전문가 무작위 감사)를 포함시켜 체크리스트 오류를 보정할 것.
- 피드백→데이터 설계: 진단은 상대 결손(Δrel)과 절대 약한 점수를 혼합해 우선순위를 선정하므로, 데이터 합성 시 해당 카테고리·소스 조건(가시성, 보존제약 등)을 명시적으로 인코딩해야 함(본문의 처방 Tt 구조 참조).
- 검색·합성 주의사항: 웹 기반 소스·텍스트 검색은 희소 개념 보강에 유용하지만 기존 강한 범주에는 불필요한 변동을 초래할 수 있음. 따라서 진단 기반으로 선택적 검색·쿼리 설계와 필터링을 적용해야 함(본문 관찰).
- 적응 비용·방법: 논문은 LoRA(rank=16) 방식과 25k 합성 예제로 유의미한 개선을 보였으나(특히 낮은 출발점의 FLUX.2), 하드웨어(32 MLU590)·생성 백엔드 접근성·합성 품질 필터링이 재현성·비용에 큰 영향을 줌. 실무에서는 소규모 실험으로 우선순위 검증 후 예산 확대 권장.
- 안전·윤리·배포: 체크리스트에 정치 심볼·저작권·개인식별 등 민감 항목(예: 정치심볼 편집 항목 존재)이 포함되므로 합성 데이터 생성·배포 시 저작권·프라이버시·정치적 민감성 정책을 엄격히 적용해야 함(데이터·태스크 구성에서 해당 작업 유형 명시).

**근거 범위:** 이 분석은 제공된 논문 PDF 본문(본문, 표, 부록 사례 및 실험 설정)을 근거로 작성함. 본문에 명시된 수치(예: 인스턴스 수 2,740, 작업 유형 148, 모델별 점수, LoRA·25,000 예제·32 MLU590 등의 실험 설정, gemini 기반 판정자/오케스트레이터 사용)는 PDF에서 직접 확인한 값임. 다만 PDF 텍스트 추출 과정에서 일부 중복·절단된 페이지가 있어 세부 구현 파라미터(예: Train 함수의 하이퍼파라미터 λt 구체값, 합성 백엔드의 정확한 모델 구성)는 본문에서 구체적으로 제시되지 않았거나 부록의 다른 파일에 있을 수 있으므로 해당 항목은 본문에 명시된 내용만으로 보고되었음을 밝힘.
